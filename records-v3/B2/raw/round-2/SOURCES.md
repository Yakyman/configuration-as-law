# Round 2 source basis

Read before implementation probes; records use UTC. The tests exercise the assembled mechanism, not the already documented facts below.

- [Linux chroot manual](https://man7.org/linux/man-pages/man2/chroot.2.html): “This call does not close open file descriptors”. The snapshot is only a pathname view. The launcher additionally changes cwd, closes descriptors, permanently drops all groups and uid/gid, and applies AppArmor, Landlock, no_new_privs and seccomp. It cannot use chroot as a standalone security claim.
- [Linux seccomp manual](https://man7.org/linux/man-pages/man2/seccomp.2.html): “existing filters will be preserved across a call to execve(2).” Architecture checking and denied syscalls apply to descendants and later exec, not only to one executable name.
- [AppArmor parser manual](https://manpages.debian.org/unstable/apparmor/apparmor_parser.8.en.html): “Writes a binary (cached) profile to stdout”. The verifier compares that compilation with the kernel-exported loaded policy objects, not just a source checksum or profile name.
- [AppArmor technical documentation](https://gitlab.com/apparmor/apparmor/-/raw/apparmor-4.0/parser/techdoc.tex): “Retrieving information about files is always allowed.” Exact read rules and Landlock alone do not conceal writable-file existence. The final input snapshot contains no ordinary-writable tree or procfs, and explicit stat/O_PATH/name-to-handle oracles test that distinction.
- [AppArmor kernel interface](https://gitlab.com/apparmor/apparmor/-/wikis/AppArmorInterfaces): loaded raw policy exports supply the effective-policy comparison. Integration failures of revision streaming, magic links and transaction grouping were retained in ITERATIONS.md.
- [Kernel Landlock documentation](https://docs.kernel.org/userspace-api/landlock.html), [no_new_privs](https://docs.kernel.org/userspace-api/no_new_privs.html), [seccomp filtering](https://docs.kernel.org/userspace-api/seccomp_filter.html) and [systemd execution](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#MemoryDenyWriteExecute=): the separate independent review in REVIEW.md records the quoted constraints and why no single mechanism suffices.
