# Round 3 harness expectations

Recorded 2026-11-22 UTC, before fresh-VM execution. This file records intended observations, not results. The source requirements are `S3-4`, `S3-5`, `S2.4-4`, `S2.1-4`, Section 4.4, and (not published: orchestration and working notes). Existing mechanism documentation is quoted in `../../../B1/raw/mechanics-sources.md`: file and directory fsync, atomic rename, cgroup process revocation, systemd state observation, and effective firewall observation. Those sources establish individual primitives; they do not answer whether this testbed composes them correctly. The following are integration assertions, not repeated probes of documented Linux behavior.

| Assertion family | Input and expected observation |
|---|---|
| FAIL-* | Root-only test hook injects failure at prepare, frozen, quiesce, files, accounts, rules, policy, jobs, readback and commit-ready. Candidate changes recorded program bytes, removes service, rule and account, and introduces distinct program, service, account and rule contributions; all newly introduced contributions must be absent after rollback. Failure must report literal `FAILED restored previous declaration:`, produce no success marker, leave no pending journal, and restore the readiness marker containing the former generation. It must preserve the former selected generation and exact success report, and restore all former `stand-compare` values with successful every-line verification. A recovery-incomplete report fails even if observed old values happen to match. |
| STALL-PREPARE, STALL-FILES | Root-only hook stalls the worker before inert preparation or after file activation. The total one-hour deadline is shortened to 60 seconds, with worker cancellation at eight seconds (production: cancellation at 3300 of 3600 seconds). The explicit restoration-report, no-pending, readiness-marker and unchanged-success-report checks above also apply. The external command timeout is 90 seconds and the assertion's recovery bound is 60 seconds; restoration must finish by the shortened total deadline, not merely start at cancellation. Production restoration timing must be assessed separately from these test settings. |
| WATCHDOG-SUPERVISOR-DEATH | Stall after files with worker timeout eight seconds and total deadline 60 seconds; wait for the durable worker identity, SIGKILL only its supervisor, then require the independent timer to kill the orphan worker and restore prior generation/report/every-line values with no candidate extras or pending transaction. |
| REMOVAL-* | A declared native program forks; a declared service runs it with timer and Unix-socket activators. A rule is active. Complete removal must stop observed relay/worker/descendants, remove active code snapshot and original paths, leave activators inactive and disabled, remove socket and effective rule, and deny ordinary attempts to start retained copies and reactivate former units. |
| SHARED-* | Two explicit declarations overlap for each of program files, service, timer, socket, account and rule. Removing original owners preserves exact bytes/launch membership, running descendants, enabled active units, socket, account numeric identity and the remaining effective rule. Every-line verification must pass. Removing the last owners revokes all those contributions and denies launch; surviving explicit lines state the required state. |
| SESSION-REPLAY-GATE | Operator removes the readiness marker; an ordinary positive data-tool request must fail. Marker is restored afterward. |
| BOOT-SESSION-GATE | Operator installs an eight-second replay ExecStartPre delay. Actual ordinary SSH requests are attempted throughout boot before controller readiness. Logs record every refusal/success. The SSH listener may start before replay so the declared port can be verified. The PAM requisite account gate must be present; operator login attempts must never return the premature-session marker. At least one ordinary request must occur before the first observed operator BOOT_READY response, and none of those requests may succeed. This observation boundary is conservative: a request spanning the transition may fail the test rather than falsely pass it. Service-manager dependencies for login/getty/session entry are inspected. The test delay is removed afterward. |
| POWER-ADD/CHANGE/REMOVE-1/2/3 | Nine cuts: SIGKILL QEMU immediately after the first received SUCCESS marker; record marker-to-signal delay. Boot must select that exact generation, retain matching last-success, leave no pending transaction and pass every-line verification. |
| INDEPENDENT-RECIPE-COMPARE | Driver requires a separate root containing an independently rebuilt image, applies the development declaration in fresh VMs of both roots, compares every declaration file byte and every observed value. Different image hashes do not alone prove independent rebuilding; separate complete recipe logs are required. |
| Regression | Entire original D suite and BC1/BC2 suites on fresh overlays of the rebuilt image, plus the inventory agent's separate fresh-VM fixture. |

`round3-driver.py PHASE --peer-root PEER` creates a new evidence folder `raw/round-3/PHASE`; it refuses reuse. `--skip-regressions` is only for integration development and must not label the final rebuilt-image run. Application command output is logged before any snapshot read; failed snapshot rows retain their observed mismatch values. A failed transaction assertion aborts subsequent dependent boot and power-cut work. Independent peer comparison invokes the installed `stand-compare` on both exported snapshots, retaining per-line output. The driver does not rebuild images: the operator supplies the two completed recipe builds and retains their logs. Every created disposable VM is destroyed on exit, including error paths.

The retained-copy request tests the ordinary launcher and the live snapshot path; a separately retained native cache copy is also attempted. Whole C9.6 closure additionally requires evidence that container backends/API/daemon activation are unavailable, not just one absent container-name refusal. Firmware/device replay and unrestricted semantic inventory are not implied by passing these bounded assertions.
