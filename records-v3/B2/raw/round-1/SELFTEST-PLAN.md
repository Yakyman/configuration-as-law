# Round 1 planned regression observations

Prepared before guest execution, 2026-11-22 UTC. Source basis: `../../../B1/CHANNELS.md` C1.1–C1.6, C6.1–C6.6, C10.1–C10.3, M1.01–M1.02; `../../../SENTENCES.md` S2.3-7 and S3-3; the installed recipe files are the implementation under test. This is regression verification of a changed implementation, not repetition of the original unanswered probes.

`../../build/round1-selftest.py` runs inside a disposable guest as the external fixture operator. Each mutation attempt runs under the ordinary account, both directly and through its granted sudo authority. The operator's external access is not counted as a system-granted ordinary privilege.

Expected: original package/account/service/network/firewall executables and alternate-root, database, hook and environment paths refuse by access control; absent schedulers count only as removal, not as an authority error. System D-Bus mutation attempts must report an access denial, not an absent object, invalid signature, or unavailable radio. Copies of protected backend binaries and library entry points must refuse. User-manager starts, persistent units/drop-ins/generators and cron/at must not activate undeclared work. General-purpose shell sudo must refuse.

Positive controls: declaration-mediated program install/update, service and timer scheduling, account, firewall and saved network profiles work; browser and document work remain available. This does not establish system updating. Prepared Bluetooth state is not hardware pairing. Every line is read back before successful application. While the operator holds the application lock, supplied frontends and verification must refuse in less than five seconds. An invalid declared artifact must fail without selecting a new declaration. Unsafe service hooks, root services, arbitrary privilege writes and mutable program permissions must fail admission. A service required active whose process immediately exits injects a live readback mismatch: failure without SUCCESS is expected, followed by successful previous-generation verification.

Writable per-user service paths are intentionally tested as ignored: write unit, drop-in, template, alias and both generator classes, then require the private manager executable and user CLI to refuse, and independently check the system user-manager instance is inactive and no fixture marker appeared. Cron spool writes must refuse. Retained generations and package caches must be unreadable; an ordinary copied declared native worker must remain nonstartable both directly and through the dynamic loader after removal. This is bounded native evidence, not general interpreted-byte revocation.

Output: JSON lines include test ID, variant, account context, exact command, expected condition, exit status, complete combined output and result. A failed assertion makes the overall suite fail, but remaining independent cases continue. Positive controls are sequential because they share declared state. The suite removes its temporary documents and adversarial fixture files. The driver destroys the disposable guest.

Limits: this finite suite does not prove all interpreted/cache retained-code revocation (C1.3/C1.6), arbitrary generated code (C6.5), every surviving-child activation edge (C6.6), or complete cross-resource M1.02 semantics. Those full variants require separate evidence before closure. No hardware radio success is inferred.

Final rebuild additions, planned before its suite: `stand-compare` must also refuse under the application lock. A caller-provided PYTHONPATH module and alternate D-Bus address must not affect a supported `stand-verify`; sudo environment assignment and preservation requests must refuse. Backend configuration options at the frontend must refuse. Package-library loading uses the observed absolute file path to distinguish EACCES from a failed SONAME search. The full original suite is rerun, including full two-instance values and power cuts, after fixed tmpfs-size defaults remove incidental per-boot size variation.
