- The first complete rebuilt-image validation passes all 301 BC4 assertions, D01–D10, BC1 (166), BC2 (133), BC3 (35), boot admission and nine power cuts, but its independent-build comparison fails. The only differing actual file is `/boot/initrd.img-6.12.117+deb13-amd64`; its hashes differ, so the two captured factory declarations also differ. The controller exit 1 and failed comparison remain preserved in `rebuild-attempt-1/`. The combined stage correctly did not run. The recipe had omitted `SOURCE_DATE_EPOCH` during package hooks. The corrected bootstrap sets the pinned cloud-source date, 2026-11-16 00:00 UTC (`1794787200`), using mkinitramfs's existing reproducible mode, and the recipe logs the resulting factory and initramfs hashes before freezing. Both images must be rebuilt and the complete fresh-VM suite rerun; earlier passing components are not substituted for that run.

Source for the correction: [Debian mkinitramfs manual](https://dyn.manpages.debian.org/testing/initramfs-tools-core/mkinitramfs.8.en.html), “If SOURCE_DATE_EPOCH is set, mkinitramfs attempts to generate a reproducible initramfs image.” The [implementation](https://salsa.debian.org/kernel-team/initramfs-tools/-/blob/debian/latest/mkinitramfs) clamps archive timestamps, enables reproducible cpio metadata and avoids variable compression settings. This identifies a testbed recipe defect, not an obstacle derived from the hypothesis definitions. Expected corrected result, recorded before rebuilding: both factory manifests and initramfs hashes coincide; all full-suite and combined-declaration assertions pass.
