# Language channel implementation and expected self-tests

Recorded 2026-11-22 UTC. Sources read before implementation: `../../../B1/raw/install-sources.md` E4–E6, and the existing `../../build/codeboundary.py`, `session.c`, `guard.py` mechanisms. No new probe of documented package-manager semantics is needed.

- https://pip.pypa.io/en/stable/cli/pip_install/ documents “Local or remote source archives.” The adapter instead admits exact wheel bytes; it never invokes a source build backend.
- https://pip.pypa.io/en/stable/reference/build-system/ documents temporary build dependencies; dependency isolation is not execution isolation. Source builds and editable installs are refused.
- https://docs.npmjs.com/cli/using-npm/config/ documents “If true, npm does not run scripts specified in package.json files.” Explicit run/start/test is a separate route: all are refused by this adapter.

`language_channels.prepare(tool,args)` returns one managed program row for a whole locked project. CLI grammar: `pip install --stand-lock /path/pip.lock.json` or `npm install --stand-lock /path/npm.lock.json`. `pip3` is an alias. The source lock and original archives become checksummed installed files and identifies every package by exact version, original source URL, SHA256, dependency edges, and a checksummed project entry. Wheel metadata and npm package metadata are checked against the lock; unresolved dependencies, unsupported dependency constraint syntax, archive links, unsafe paths, overlaps, wheel `.pth` and relocation entries are refused. Admission validation re-derives the entire row from its stored lock and archives and rejects any metadata/file discrepancy. Archive expansion only creates declaration payloads, never executes a build backend or lifecycle script. All archive files, including any scripts, are recorded before activation. The existing broker writes `/opt/stand/pkgs/`; the sealed launcher exposes the immutable declaration input tree only, fixes entry arguments and environment, and denies executable anonymous memory. Node requires `--jitless --no-expose-wasm`.

Development positives are genuine distribution artifacts: python-dateutil 2.9.0.post0 with six 1.17.0; is-odd 3.0.1 with is-number 6.0.0. `language-fixtures.py` downloads on the server using exact URLs and SHA256 values baked into the recipe; npm artifacts additionally have fixed SHA512 values. Existing artifacts and locks are verified and reused, never silently replaced. Initial digest acquisition used package-index release metadata; subsequent builds and application do not fetch that metadata or execute a resolver.

Expected self-tests (`language-selftest.py`): ordinary and sudo installs succeed; fixed recorded entries print `PIP_POSITIVE 2026` and `NPM_POSITIVE true`; custom prefix/target/user/global/workspace installs, editable/link/VCS/index/config overrides and explicit lifecycle commands refuse; changed artifact digest and omitted transitive dependency refuse; raw interpreter and extra entry arguments refuse. Whole-image verification succeeds. These are implementation expectations, not observed results; root integration must save the actual fresh-VM output before any CLOSED claim. Existing round-2 native mapping and unrecorded module tests remain relevant to C2.6; adapter tests alone do not establish its full scope.

Limits: scoped npm package names, optional/peer/bundled dependencies, Python environment-marker dependencies, `.data` relocation, `.pth`, and unrecognized constraint forms are refused. This is a finite package-format adapter with general exact-project admission, not a full pip/npm implementation. Build/lifecycle workflows can be submitted as separate recorded code through the common importer; this adapter never runs those workflows at install time.

Parser integration results on the server are saved in `language-parser.log`: both upstream projects validate; altering derived package-version metadata is refused. This is not yet VM runtime evidence.

Pinned offline-cache validation succeeded in `language-pinned-cache.log`.

Additional integration attempts: actual source-backend archive with pyproject/backend hook; actual libm copied into mutable storage and loaded by a recorded Python ctypes entry; ordinary copy-overwrite of managed entry; removed entry and its copy launch. All must fail without hook/native marker; copy as inert data and reinstallation must succeed. These rows are implemented in the self-test, with observations pending.

Native-extension positive: `language-native-fixture.py` runs inside the image builder, wraps its exact CPython `_bz2` extension in a deterministic wheel with standard METADATA/WHEEL/RECORD and fixed ZIP timestamps, and emits `pip-native.lock.json`. The recorded project asserts the loaded module path is the managed wheel directory and performs native compression and decompression; removal must revoke the entry. No native compilation or external mutable input is required. Successful original pip/npm rows are exported by the self-test under `/var/lib/stand/channel-examples/`.
