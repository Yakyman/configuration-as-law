## Mechanisms and evidence

- **Supervised application and restoration:** `build/transactions.py` owns the child process group, pending journal, cancellation, durable success report and independent systemd recovery timer. `build/stand.py` reconciles the union of candidate/target activation edges and contributions. All ten failure checkpoints and two shortened stalls require the previous report, generation and every actual value, absence of candidate-only artifacts, cleared journal and readiness marker. The separate supervisor-death case requires timer-driven recovery. SELFTEST T01–T03 pass on the rebuilt image: all ten failures, two worker stalls restored in 27.28/27.41 seconds, and independent supervisor-death recovery in 29.14 seconds. Production worker cancellation is 3300 seconds within a 3600-second interval; tests explicitly use eight and 60 seconds. M3.02 is not inferred from finite restoration tests.
- **Durability and boot admission:** a completed realization is synced before the durable atomic local report; stdout forwards that report. Boot replay follows the report, then publishes a volatile ready marker. PAM account admission, the ordinary launcher and session-manager dependencies gate sessions. SELFTEST T06 delays replay: 167 early ordinary login attempts all refuse and no premature operator session appears. T07 passes three add, three change and three remove SIGKILL cuts 0.213–0.482 ms after receiving success, with the exact reported generation and all required values after each boot.
- **Removal and residual coverage:** existing systemd cgroups, socket/timer withdrawal, AppArmor membership and process revocation precede file/input-root replacement. Exact remaining file, unit and account claims preserve contributions; nftables receives the rules from remaining explicit lines. T04 proves actual socket activation before removal, then attempts original/copy/cache/snapshot launches, manager reactivation and socket connection after removal. T05 removes one of two explicit owners, then the final owner, across program/service/timer/socket/account/rule contributions. Unsupported activation directives still refuse admission.
- **Independent inventory:** `stand-inventory` walks actual objects before matching required state to declaration lines; it includes mounted filesystem trees, managers, accounts/rights/keys, rules/listeners, saved profiles and accessible boot/runtime state. T08 plants every listed fixture kind directly as external root. The census reports `complete:false`, `p1:"?"`; unknown semantic code and unreadable firmware are visible limitations. `stand-verify` supplies per-line P2 readback and inventory supplies bounded P1 evidence. See [INVENTORY-3.md](INVENTORY-3.md).
- **Independent rebuilding and regression:** Two complete recipe executions use the pinned source with the same verified package archives and explicit laboratory key inputs. T09 passes: complete declarations are byte-identical, and the installed `stand-compare` reports all 498 actual values equal with successful readback on both sides. T10 passes the original D01–D10 suite, all 160 BC1 tests, and all 129 BC2 result rows plus three assertions on the rebuilt image. Build roots and disposable overlays are distinct; a copied finished image is not the second installation.
