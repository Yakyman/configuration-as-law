## Finding 1 — restore C10.4 as TEXT-OPEN

Supported. S3-6 says: “**Built-in tool.** A program of the system whose purpose, according to its documentation, includes changing what must be recorded: a package manager, including package managers of programming languages and of application packages; account and rights management; the service manager; network and firewall configuration.” S3-7 says: “General-purpose programs—an editor, file copying, link creation, the command shell—are not built-in tools: changing with them, through superuser privileges, what must be recorded is breaking.”

The documented package-install operation is saved in `../raw/ordinary-sources.md` O6 and `../MECHANICS-research.md` C10.4: the package-install documentation says “then downloads and installs it.” The concrete case is an editor installing packages containing code executed with its own rights, so S2.2-10 requires recording. Reading A applies documented purpose under S3-6: installation past the declaration violates S2.3-7 even with superuser privileges. Reading B applies the express editor exclusion under S3-7: the privileged change is breaking and excluded. The text provides no priority between these descriptions of the same program. Classifying by operation or mode would add a rule; do not do so. Restore the original card and delete the categorical exclusion in CHANNELS. Restricting the editor's installer is an implementation option, not resolution of this textual conflict. S3-8 and Section 4.1 govern the eventual definitional outcome.

## Finding 5 — conditional custom interpretation failure

Supported with a scope qualification. Add a C7 variant in which recorded M interprets an unrecorded file F using its own dispatch loop, without entering eval, source, import, or an execution-check API. State explicitly that F is a program in M's interpreted language and that this language gives it the interpreter's own rights. Merely reading values or providing a few fixed operations does not establish that premise. S2.2-13 says: “A file that a program executes as code counts as code even when it holds settings; a file that a program only reads as values counts as a setting;”. S2.2-10 requires the own-rights premise, not simply a file read followed by an effect.

Given that premise, after completed application and without breaking, F is code required by S2.2-10, is in force under S2.1-3, and is unrecorded, contrary to S2.3-4. Ordinary unprivileged supply of that code past the declaration also contradicts S2.3-6. Checking only standard evaluator entry points does not cover M's interpretation loop. This proves failure of the admitted combination of arbitrary scripts, own-rights interpretation, and access to unrecorded inputs. It does not prove every system must admit that combination; NOT-CLOSABLE would overstate Section 4.1.

Recommend C7.08 and the new file-based variant CLOSABLE through D at the explicitly accepted cost, and remove the unsupported “or F” alternative from C7.07. Evidence for D is `../raw/c7-sources.md` E12: restricting file reads prevents this opening of unrecorded F. Its scope is essential: install restrictions before descriptors are opened; deny or account for inherited descriptors; argv, environment, terminal input, and stdin are separate ingress routes, not automatically closed by pathname read rules. The result must not certify arbitrary-input interpreter closure. Ordinary scripts lose direct access to unrecorded documents/project data; any proposed mediated reader needs its own coverage evidence. A reader delivering unrestricted bytes to arbitrary scripts recreates the same custom interpretation issue.

Q1 should remove the cooperative-evaluator control as a general solution to arbitrary admitted scripts with data access. It may be described only as a candidate for identified evaluator entries with established coverage, not as closing the custom-dispatch route. C2.6 and C4.4 should inherit this limitation. No undecidability theorem or inference that every readable document is code is needed.

## Finding 7 — preserve both independent Q2 choices

Supported. S2.4-1 says: “**Understanding.** If there was no breaking, what is in force on the computer can be read from the declaration alone, without inspecting the computer.” S2.5-3 says: “Nor is the form of the declaration part of the definition: it may be a list or an algorithm that computes what is recorded.”

Keep the two-computer construction from CHANNELS Q2: identical designated declaration files, differing external D, and separate applications whose computed recorded and in-force sets differ. Specify that P4 does not fail merely because the inputs differ between separate applications: this construction need not permit any undeclared change after application. P1/P2/P4 satisfaction remains a premise of the textual argument, not a measured testbed result.

Preserve these two independent author choices without selecting either:

1. **Consequence versus admissibility filter.** On the consequence reading, Understanding is claimed to follow from P1/P2/P4 even with the algorithmic form allowed by S2.5-3; the construction challenges that implication when the external-input arrangement is admitted. On the filter reading, Understanding additionally excludes that arrangement from admissible declarations. CHANNELS currently selects the latter by saying S2.5-3 does not compel acceptance and calling the condition a compatibility requirement. Present that only as one reading.
2. **Concrete objects versus symbolic description.** On the concrete reading, identical declaration files cannot identify different concrete in-force sets without inspecting external D. On the symbolic reading, reading the rule “every script in D” may itself satisfy Understanding without enumeration. The text supplies no express choice; do not refute the second merely by restating the first.

Record Q2 as a textual question/hole with both choices and their consequences; it is not an additional installation channel. Delete categorical “not a fourth hole” or equivalent conclusions in CHANNELS and DESIGN-INPUT. Distinguish this interaction between stated requirements from the permitted design choice of declaration form itself: S2.5-3 alone is not a hole. If D is among the designated declaration files, or cannot change the computed result, the constructed information deficit disappears. That does not settle the stated external-D case. No universal impossibility follows, and no failure condition is changed.
