# Design input for the new testbed

Recorded 2026-11-22 UTC. Read alongside `CHANNELS.md`: **bounded mechanisms exist, but a complete P1/P2/P4/Removal system has not been established; outcome ?**. No testbed was built. The list below is a minimal combination of control responsibilities, not a claim of mathematical minimality or a ready-made distribution configuration.

## Exact available version pins and evidence limits

Use **Debian 13.8 amd64**, released 2026-11-21, with the explicitly selected **trixie-backports kernel package `7.3.4-1~bpo13+1`, image `linux-image-7.3.4+deb13-amd64`**, and **systemd `257.13-1~deb13u1`**. These versions were checked in primary release/package pages and subsequently booted in the disposable P01 VM. The kernel requires backports `linux-base 4.17~bpo13+1`; select the backports dependency set explicitly. Actual package versions and required kernel configuration options are saved in `raw/vm-versions-output.txt`. Debian stable's default kernel is instead `6.12.117-1` / `6.12.117+deb13-amd64`; do not silently attribute the newer API to that default. Upstream latest stable at source access was 7.3.5 (2026-11-17), distinct from the available Debian backport. [Evidence: `raw/ordinary-sources.md` V1–V6; `raw/install-sources.md` E27–29.]

The execution-check API and locked `SECBIT_EXEC_RESTRICT_FILE` / `SECBIT_EXEC_DENY_INTERACTIVE` are present in versioned **Linux 6.14** documentation and the `inc` source example, with `set-exec` also verified in source package 7.3.4-1, and documented again for **Linux 7.3**. Linux 6.12 already documents `cgroup.kill`; systemd 257 documents control-group stopping and the mature memory-execution restriction facilities. These establish supported upstream primitives at the selected newer kernel version, not an enabled or correct boot policy. [Evidence: `raw/c7-sources.md` E1–5,E16–19; `raw/c7-pinned-source-checks.json`; `raw/mechanics-sources.md` E5,E6.]

Before the actual testbed's first observation, the builder must pin package checksums, kernel build configuration and boot LSM selection, source versions of all cooperating evaluators, policy and the concrete declaration/ordinary commands as Section 4.1 requires. Required configuration includes dm-verity, enforcing SELinux (or one equivalently complete mandatory policy), seccomp filters, cgroup v2, and the execution-check ABI. The package pages alone do not establish these runtime choices. No claim is made that a distribution ships the needed interpreter/editor patches. The demonstrated adopter is the limited Linux 6.14 sample interpreter; CPython verified-open/audit facilities are integration points, not a complete sandbox. Production Bash/Python/glibc adoption across all input paths is unestablished (`raw/c7-sources.md`). P01 specifically establishes that Debian Python 3.13.5, package `3.13.5-2+deb13u5`, executes `-c` code as uid 65534 with both securebits and locks (`0xf00`) retained across exec. Setting the bits alone does not close that route for this binary (`raw/python-securebits-output.txt`). The other input paths were not probed.

## Three responsibilities to combine

1. **One protected active code generation and one mutation authority.** Keep code and declared executable settings in a read-only verified tree (dm-verity with the expected root bound to the declaration). Use enforcing mandatory policy to allow execution and executable mapping only from the current declared closure, not any publisher-signed file or retained store path. Writable home/download/cache/container layers are data until admission. Gate namespace/mount creation, native memory execution, memfd, ptrace/process-memory writes and alternate syscall ABIs; use syscall restrictions only as a complement to mandatory policy. Browser rendering needs its own genuinely confined domain, so a global JIT prohibition is unsuitable. Package, service, network, account, firewall and container frontends—including privileged invocations—must submit changes to a broker; neither direct backend paths nor daemon/D-Bus/netlink APIs may retain independent mutation authority. This closes the bounded native/install/manager routes in C1–C6/C9/C10 and C7.11–16,22–23, subject to responsibility 2 for interpreted inputs. [Install E3,E10–12,E15–25; interpreter E3–5,E11–12; ordinary O7–9.]
2. **Admission at each code-consuming interface.** Retain at least one real declared interpreter path; do not solve C7 by deleting the channel. Cooperating interpreters check the exact immutable file descriptor with `AT_EXECVE_CHECK|AT_EMPTY_PATH` and enforce both locked securebits. Every import/source/plugin/library path needs the same decision. Refuse unrecorded -c/-e, REPL, pipe/socket/FIFO/here-document, environment and command-line code; a declared file can supply the equivalent supported operation. A restricted interpreter domain can instead deny all unrecorded input reads, including inherited descriptors and IPC, but loses general data-processing flexibility. Values-only document tools and genuinely confined webpages remain usable. Record host-executed build scripts before launch or run construction inside a recorded full-system VM; container isolation is not that exemption. C7.08/C7.10/C8.04 remain UNKNOWN if arbitrary data access and evaluator features are retained. The existence of the small `inc` example does not certify a Python/npm toolchain. [Interpreter E1,E2,E6–10,E13–16; install E4–6; S2.2-10–13.]
3. **A generation application supervisor with explicit lifecycle verification.** Serialize preparation, activation and reporting. Stage code, policy and generated configuration without making candidates active; validate finite declared values and dependencies. Bind the durable report to the exact generation; check write/fsync errors and parent-directory durability. Reboot may be used for activation and complete userspace replacement. Removal revokes launch permissions and every activation edge, then terminates all holders and waits for absence before success; a full session restart or reboot is acceptable but does not replace permission revocation. Failure/one-hour timeout retains the previous declaration, requiring rollback of live/device state as well as files. Compare every line and separately detect extras. Existing primitives close the bounded M1.01/M2.01/M3.01/M4/M5.01 cases; the complete cross-resource report/recovery protocol remains UNKNOWN. [Mechanics E1–12; ordinary O1–3.]

This is deliberately not a stack of every candidate. fs-verity plus an authorization policy can replace a verified tree for some designs; IMA appraisal/EVM or IPE can supply integrity enforcement but do not know active declaration membership or arbitrary interpreted code. fapolicyd is an alternative file-access enforcement component whose trust source, integrity checks, coverage and failure behavior need integration. Landlock can constrain selected processes/descendants; it is not the sole global authority. Adding all of them cannot replace the evaluator and transaction responsibilities. Nix/Guix-style retained stores, OSTree/image deployments, ChromiumOS and Android are useful precedents, not evidence that the stricter current-declaration Removal and report requirements already hold. Mechanism-specific costs and open paths are in the source ledgers and supporting research.

## What this design cannot certify closed

These are precisely the non-CLOSABLE rows in the main inventory; no NOT-CLOSABLE or CLOSABLE-ONLY-BY-REMOVAL row is established.

- **C7.08 — UNKNOWN:** arbitrary data-to-code conversion/custom import loaders while retaining general data access.
- **C7.10 — UNKNOWN:** complete mediation of general embedded interpreters.
- **C8.04 — UNKNOWN:** full programmable-editor configuration/plugin/eval mediation.
- **C10.3 — UNKNOWN:** unrestricted retained privileged hooks with multi-resource live side effects.
- **M1.02 — UNKNOWN:** whole-state activation and success reporting across all recorded objects.
- **M2.02 — UNKNOWN:** complete runtime/device reconstruction after immediate power cut following add/change/remove success.
- **M3.02 — UNKNOWN:** complete old-state restoration after partial activation failure or the one-hour no-report boundary.
- **M5.02 — UNKNOWN:** validation of unrestricted algorithmic/semantic requirements.
- **C7.18 — TEXT-OPEN:** genuinely regenerable executable bytecode/JIT cache: cache exemption versus same-rights code requirement.
- **C8.07 — TEXT-OPEN:** locally acting browser extension containing browser-equivalent privileged code: extension example versus own-rights code requirement.
- **C7.21 — TEXT-OPEN:** WASI module with a preopened host directory and fewer rights than the runtime: the boundary of the program's own interface.

UNKNOWN is not NOT-CLOSABLE. Restricting unsupported features may avoid an unresolved implementation obligation while retaining six ordinary actions; it cannot be reported as proving every arbitrary application supported. A TEXT-OPEN object can conservatively be recorded or disallowed, but that does not settle the text's classification. The Q2 external-directory algorithm is not a fourth hole: the permitted algorithmic form does not waive declaration-alone Understanding; its concrete input dependency must be assessed as described in CHANNELS.

## Ordinary work retained by the design, with actual acceptance still pending

Installation/update use declared artifact closures and the broker; Wi-Fi uses declared saved-profile settings and brokered NetworkManager operations; Bluetooth uses declared device/bond/trust policy and brokered BlueZ pairing. Browser use retains a recorded browser/component closure with the explicit confined-webpage exemption; document editing retains recorded editors with values-only or controlled content paths. Personal scripts use write–admit–apply–run; pip/npm use managed immutable environments and recorded or VM-contained build inputs. Each field/tool requirement and loss of convenience is specified in Q3 of `CHANNELS.md`.

A design that disables network management, Bluetooth pairing, all document editors, all browsers or all positive examples of a channel fails the stated task. No evidence here establishes that those removals are necessary. Hardware pairing/connection and the whole composition were not tested. One VM probe resolved the narrow stock-Python adoption question after source inspection; no other already documented primitive behavior was reprobed. `raw/PROBE-DISPOSITION.md` records why the remaining unknowns cannot be discharged by a single-mechanism probe. The VM, disk, seed and keys were removed, and the slot released (`raw/vm-cleanup-output.txt`).
