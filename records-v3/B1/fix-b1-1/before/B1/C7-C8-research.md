# C7 and C8: interpreter and executable-setting channels

Research date: 2026-11-22 UTC. Scope: C7 and C8 only. Source records: `raw/c7-sources.md` (E1–E16) and `raw/c7-pinned-source-checks.json`. No experiments or testbed were built.

## Requirements fixed by the text

S2.2-10: “code that another program executes must be recorded if the program runs it with the program’s own rights, so that the code can do whatever the program can do: scripts executed by an interpreter (python, bash), shell startup files, an editor configuration written in the editor’s programming language.”

S2.2-13: “A file that a program executes as code counts as code even when it holds settings; a file that a program only reads as values counts as a setting;”

S2.1-3 makes code that runs **or can be started** in force. Therefore recording the interpreter alone does not record arbitrary scripts it can consume. S2.3-4 requires all such code in force to be recorded; S2.3-5 requires recorded code available as its line requires; S2.3-6 forbids bypass paths. S3-7 does not exclude unprivileged shell/editor changes: breaking requires superuser privileges. S2.4-4 requires closing re-execution and terminating what a removed line contributed, unless another line covers it.

Definitions of mechanisms in the table:

* **F**: immutable declared code plus kernel execution/mapping policy and cooperative interpreter checks on the exact open descriptor. Mutable directory membership, executable bits alone, a verified root alone, and noexec alone are insufficient.
* **I**: interpreter denies unrecorded argument, stream and interactive code before evaluation. Linux v6.14 `inc` is an actual small-language implementation showing this can be done; it is not a drop-in substitute for Bash/Python.
* **R**: enforce read denial for unrecorded code inputs in a restricted interpreter domain; retain declared inputs. Must include inherited descriptors and IPC delivery. This sacrifices that domain's general arbitrary-data access, while separate document/browser tools can remain usable.
* **N**: deny native execution and executable mapping from files not in the declaration; deny executable memfd and anonymous write-to-execute paths for ordinary native execution domains. This includes loader and shared-object paths.

A CLOSABLE result below is for the bounded variant and named mechanism. It does not assert that the entire C7 union is closed by stock distribution binaries. The UNKNOWN rows prevent that stronger claim. CLOSABLE-ONLY-BY-REMOVAL is not assigned merely because removal is the easiest currently known option: “only” would require excluding adaptation and mediation.

## Channel × mechanic obligations

These are obligations for every applicable variant above, not extra counted variants. An execution-control mechanism alone does not establish any complete-system M1–M5 guarantee.

| Channel | M1 successful application | M2 immediate power cut | M3 failure or hour without report | M4 removal | M5 compare every line |
|---|---|---|---|---|---|
| C7 | Publish success only after declared interpreter/library/script closure and active access policy agree (S3-3; S2.3-4–7). Stop execution of changed code during transition. | Persist code, manifest, authorization policy and boot selection before report; rebuild same policy before untrusted input at reboot (S3-5). | Old declared code and authorization remain available; tentative new code cannot become launchable and old code cannot be permanently revoked (S3-4). | Kill old interpreters/children and discard loaded code, old fds, bytecode copies, mappings and privileged broker handles; revoke all start paths unless retained lines cover them (S2.4-4). | Compare script/module/library identity, immutable content, required state and effective execution/read policy; a file hash list alone cannot establish a denied eval path (S2.1-4; S2.3-5; S3-9). |
| C8 | Commit startup/config code together with launch environment and interpreter policy (S3-3; S2.3-4–7). | Boot/login must use the committed startup configuration and environment; no fallback to an old executable config (S3-5). | Keep old startup/config meaning and availability until success; speculative editor/plugin reconfiguration cannot count as applied (S3-4). | Existing shells/editors must lose functions, aliases, plugins, autocmds and other loaded code from removed lines, normally by process restart or session termination (S2.4-4). | Compare every source of executable settings, not just one conventional rc path; include alternate config path, environment and project-local configuration (S2.1-4; S2.3-5; S3-9). |

## Written impossibility arguments

No NOT-CLOSABLE result is established for C7/C8. A stock interpreter bypass is a testbed limitation, not an argument from the definitions that all Linux systems fail. In particular, Section 4.3 does not require unrestricted REPLs, ctypes, shell snippets, arbitrary plugins, or a specific editor. The fixed six ordinary tasks do not entail retaining an unrestricted interpreter. Conversely, removing every interpreter would evade the specified positive declared-program C7 example; a testbed must retain a controlled declared script-execution path.

A useful conditional argument for Q1 is definitive but not a universal impossibility argument. Premises: S2.2-10/13 require a data-labelled file to be recorded when executed with interpreter rights; S2.1-3 includes ability to start it; S2.3-4 requires recording. If an unrecorded file is accessible as code to that interpreter after successful application without breaking, P1 fails. S2.3-6 also fails if a user can introduce that file through a bypass path. Strongest objection: the recorded interpreter authorizes its inputs. Answer: S2.2-10 explicitly requires the executed code itself recorded, so mere interpreter identity is insufficient; only a remaining declaration line actually covering that code can answer the objection. A system can avoid the premise by denying the conversion, recording the code before enabling it, or confining genuinely exempt code under S2.2-11. No observation of stock Python changes that logical quantifier.

## TEXT-OPEN cards

**T2 — Executable cache (C7.18).** A regenerable bytecode or JIT cache may satisfy S2.2-5 exactly: after removal, the computer does the same, only more slowly. The same bytes can satisfy S2.2-10 when they are executed with the interpreting program's rights. Cache-priority reading permits the cache without recording; code-priority reading requires its code covered before execution. The text gives no priority for this overlap. This concerns a cache that actually meets both predicates, not every .pyc file: a sole remaining executable artifact whose source is absent need not meet the cache exemption. A system can disable this cache or record it without settling which requirement applied.

**T4 — Same-rights browser extensions (C8.07).** S2.2-7 expressly names browser extensions among exempt local settings, while S2.2-10/13 require same-rights executable code. Where documentation establishes both predicates, one reading gives the explicit extension exemption priority; the other gives the own-rights executable-code requirement priority. No sentence supplies priority. Actual limited-rights extensions may avoid the conflict; unrestricted native helpers are separately required programs under S2.2-9/12. Systems can disable conflicting extensions or record them, but that does not resolve whether the text required their recording.

## Inputs to Q1–Q3 and design

Q1: yes only if every own-rights code input is already covered or denied until declaration-mediated application; the data filename or lack of executable bit gives no exemption. Stock noexec plus a recorded Python interpreter does not suffice. The difficult retained feature is arbitrary data-to-code conversion, not detection of familiar filename suffixes.

Q2: no new C7-specific resolution. A declaration that depends on an external mutable directory cannot identify its members from declaration files alone. Interpreter allowlists derived from such a scan would need frozen membership recorded in the declaration for the declaration-alone reading. Do not treat this as permission to amend the fixed text.

Q3: recording personal scripts is compatible with F if each code dependency is declared before it becomes executable. General Python projects using eval, custom import hooks, FFI or executable serialization require the controls identified; general data-to-code conversion remains UNKNOWN and executable cache overlap remains TEXT-OPEN. pip/npm dependencies must become immutable declared inputs and cannot execute unrecorded installation hooks before commitment; this needs transaction design from C2. Removing interactive programming convenience is not by itself failure of one of the six fixed ordinary actions. Browser and document tasks need recorded executable/library closures and values-only or properly confined content paths. A blanket ban on JIT or programmable documents can reduce supported applications, but it has not been shown that all browsers or all document editors require those features. Do not call loss of Vim plugins loss of document editing.

Exact support established here: upstream Linux 6.14 API and sample interpreter; CPython verified-open/audit hooks since 3.8; systemd MemoryDenyWriteExecute since 231. No exact current distribution package set has been established that closes the complete retained Bash/Python/editor paths. Pinning a recent kernel does not repair that missing evidence. Design must either supply reviewed cooperative implementations or keep C7.08/C7.10/C8.04 UNKNOWN. No probes were requested because the main failures and feature limitations are already stated by primary sources; a full implementation audit is not a minimal single-mechanism VM probe.
