# Probe disposition

Recorded 2026-11-22 UTC. One mechanism probe (P01); one disposable VM with one setup reboot; no testbed built. Read-only server preflight is in `preflight.txt`. Slot 2 and the disposable disk were released/removed after P01 (`vm-cleanup-output.txt`).

The method required documentation before experiments and prohibited probing an already answered question. The following dispositions were made before any experiment:

- noexec versus direct native/shebang execution and explicit interpreter reads: answered by mount documentation and the pinned ChromiumOS design (install E3/E14, interpreter E9). Do not repeat the bypass.
- Direct loader, LD_PRELOAD and executable mapping; memfd; anonymous writable-to-executable memory: answered by ld.so, IPE, memfd and systemd documentation (interpreter E3–5/E11). A successful denial in one policy would not establish complete semantic mediation.
- AT_EXECVE_CHECK and locked execution securebits: behavior and an actual limited interpreter are available in Linux v6.14 documentation/source (interpreter E1/E2/E16). No probe is needed to infer the documented cooperative requirement. Production interpreter adoption remains incompletely established: selected pinned files were inspected, not every downstream release. This left one specific downstream-build question eligible: P01 tests fresh unprivileged Python argument-code execution after setting both locked bits. It ran once, after `python-securebits-plan.md` recorded the expectation and after guest package/kernel verification. `python-securebits-output.txt` shows euid=65534, bits=0xf00 and successful code execution. This negative adoption result is restricted to that binary and route; it does not certify every input path or establish universal unclosability.
- File unlink, open FDs, mappings and cgroup descendants: answered by unlink/mmap/cgroup/systemd primary documentation (mechanics E5–8). No duplicate process-lifetime demonstration.
- Package frontends, hooks, language build isolation, editable paths, Flatpak scopes, AppImage extraction, transient units, cron and rootless container routes: answered by the relevant upstream manuals (install E1–20). No ordinary install is a useful unresolved mechanism experiment.
- C7.08/C7.10/C8.04: UNKNOWN is a missing complete integration for retained arbitrary evaluators with data access. One test cannot establish complete coverage of every eval/import/embed entry. A source audit and a chosen constrained implementation are required; building that implementation is beyond the requested minimal mechanism probes and would become testbed construction.
- C10.3/M1.02/M2.02/M3.02: UNKNOWN is a missing concrete multi-resource transaction and recovery protocol. No single existing primitive's behavior is in doubt. Running a full simulated transaction would test an invented testbed, which this task forbids building. Documented staging, fsync, rename and stopping primitives are recorded separately as bounded CLOSABLE rows.
- M5.02: unrestricted semantic line validation has no chosen algorithm or finite accepted language to test. The text does not require accepting arbitrary algorithms. A timeout demonstration would not prove impossibility or a correct validator.
- C7.18/C8.07/C7.21 and the Q2 alternative symbolic reading: interpretive questions cannot be decided by a VM. Primary documentation fixes the relevant cache/extension/WASI capabilities; the text supplies the unresolved classification boundary.
- Wi-Fi and Bluetooth: the task asks which lines/tools ordinary actions require. Their documented interfaces were researched. No passed-through adapter experiment was specified or performed; actual ordinary-work hardware acceptance belongs to Check 2 and is unclaimed.
