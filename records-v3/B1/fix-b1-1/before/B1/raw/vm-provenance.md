# Disposable VM provenance and command order

One VM on the server, slot 2 held by flock for QEMU's lifetime, 2 vCPU and 3072 MiB guest RAM; unit memory ceiling 4 GiB. Commands below describe task-relative locations; connection credentials and machine identities are not published. No host package or policy was changed.

1. Download `https://cloud.debian.org/images/cloud/trixie/latest/debian-13-genericcloud-amd64.qcow2` and `https://cloud.debian.org/images/cloud/trixie/latest/SHA512SUMS` with curl `--fail --location`. The image initially reported Debian 13.7 and 6.12.117+deb13-cloud-amd64. Compare the image hash with the exact filename's official manifest entry before boot. Verified SHA512: `37cb32b320820417eb04b335afcf489bfb4cecce4a957190d09cb2bffbe02b56a1cadd62d78c6ead92aa7839d5ea65e4260f994bbb4b54490df59fdf11ee1d97`.
2. Execute `vm-prepare.sh` on the server. Its cloud-init seed injects a newly generated temporary SSH public key. No private key enters the records. The disk is disposable, resized to 8 GiB. QEMU runs in the transient user unit `cal-b1-vm` under the slot lock.
3. Send `vm-install.sh` through SSH to (not published: external working record) in the guest; execute `sh /tmp/b1-install.sh`. This updates the point release and tries the exact kernel. The initial apt selection fails because linux-base needs the backports version; no interpreter test has run.
4. Send `vm-install-backports.sh` to (not published: external working record); execute `sh /tmp/b1-backports.sh`. Selecting trixie-backports supplies the dependency. These SSH sessions run from transient server user units so they survive orchestration steps. Raw package logs are `vm-setup-output.txt` and `vm-backports-output.txt`.
5. Execute `vm-select-boot.sh` through guest SSH stdin. It explicitly chooses the generic amd64 kernel instead of the cloud flavor also selected by the image's metapackage. This is routine setup reboot, not M2 testing. Raw output: `vm-boot-selection.txt`.
6. After reboot, execute `vm-versions.sh` through guest SSH stdin. Its output is `vm-versions-output.txt`. Version checks do not run the mechanism probe.
7. Copy the preregistered `python-securebits-probe.py` to server task-local `guest-probe.py`. Execute `run-python-probe.sh` on the server once, redirecting its complete output to `python-securebits-output.txt`. The wrapper sets the locked bits, drops to uid/gid 65534, and execs a fresh Python with argument code. The argument code reads back the bits and emits the marker.
8. Stop the transient VM unit, verify it inactive and slot 2 unlockable, then delete the image, seed, generated keys, guest-known-host file and server-side task logs after collecting evidence. Final cleanup evidence is recorded separately.

The scripts record exact commands; commands are not reconstructed from the expected result. SSH uses a task-generated identity, port 22382 on loopback, and a task-local known_hosts file. There is only one P01 test invocation. Installation retries and the setup reboot are not second probes.
