# Controller interface (disposable stand only)

Install `cald.py` as `/usr/local/sbin/cald`; run as root. Compile `calctl.c` to `/usr/local/bin/calctl`. Socket `/run/cal.sock` is world-connectable; authority is determined by kernel `SO_PEERCRED`, never a request username. `calctl apply`, `calctl status`, `calctl gc GENERATION...`, `calctl rollback GENERATION`; JSON responses use `ok`, with client nonzero on `error`. Rollback is root-only: restores saved root/personal documents and applies a new generation, reactivating archived state. No setuid client needed.

Root configuration: `/etc/cal/root.json`. Personal documents: `/home/alice/declaration.json`, `/home/bob/declaration.json` (actual passwd home consulted). Personal syntax `{ "programs": { "alpha": { "version": "1" } } }`. Any personal top-level key other than programs or program field other than version is rejected. Root scope/owner changes cannot be requested. Root allowlist/denylist constrain each personal program; deny wins. Same program shared across users requires identical versions. Root must apply root edits; personal apply cannot silently activate an unapplied root change. Root apply reads both personal documents, and rejects an existing personal document that violates new policy; fix that document then apply. This stand does not automatically remove it.

Root schema: `archive` (mandatory keep/delete), `programs` mapping IDs to version/scope/owners, `policies` mapping usernames to optional allowlist/denylist, `allow_channels` mapping usernames to channel arrays, `shared` mapping shared IDs to program ID arrays, optional `system_update` request string. A changed update request invokes apt update/upgrade in the hook. Catalog IDs: alpha,beta,hello,figlet,python,node,browser. Channel names: package,pip,npm,flatpak,appimage,download,build,systemd,cron,interpreter. Only the download exception is fully exercised; other exceptions grant paths but do not ensure every required helper/daemon.

After validation controller calls `/usr/local/lib/cal/apply-policy /var/lib/cal/pending.json`. Effective document has `programs`, `shared`, `archive`, `allow_channels`, plus original `root` and applied `personal`. Hook must implement actual package/execution policy. Nonzero hook status rejects apply with captured stdout/stderr; external mutations are not rolled back. Worker `/usr/local/lib/cal/worker ID STATE_PATH` runs for alpha/beta with `CAL_VERSION` environment. Worker must only use controller-supplied values, never user scripts.

Each program has `/var/lib/cal/active/ID`, shared state `/var/lib/cal/active/shared-ID`. Active entries with no current owner move to archive. Redeclaration restores the archive directory. Full effective declarations are saved by nanosecond generation ID; current generation cannot be gc'd. Delete mode removes archive entries only when neither current nor saved generations reference them; keep mode retains indefinitely. `gc` is root-only. Shared state references count if at least one owner is present.

Known limits: system scope state is root-owned; user scope state is assigned to its sole owner (mode 0770), multiple owners use group calusers (all enrolled members can access, so broader than exact owners); no automatic discovery of derivatives or services; hooks and lifecycle operations are nontransactional; single-threaded socket permits local denial of service; no durable fsync; account names/catalog fixed; rollback configuration restoration can be partial on error; version is recorded metadata unless policy hook installs it; shared ownership is declared, not discovered. Root remains unrestricted. Neither controller nor this document establishes P4 enforcement: that depends on the separate AppArmor/package hook.
