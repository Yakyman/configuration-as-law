# Private GNU ed command-input reader candidate

This draft addresses search route089: a writable saved command stream supplied as regular standard input to `ed -s`. It is not acceptance or a numbered release. The parent owns integration and independent case review.

The exact Debian binary and source version is `1.21.1-1`. Inputs come from the retained Debian snapshot index dated `20261123T000000Z`; archive checksums are in `interpreter-inputs/ed-reader-draft/input-pins.json`. `dpkg-source --no-check` extracts already checksum-verified inputs; this recipe does not claim a new signature verification. Original executable SHA256 is `ffb4610edbf021a8940d9c4ae89befd50045e594447cc6fb844c36fd5166616b`. Candidate SHA256 is `9c9821ab6caf3422c61380691914078dadfa8aa920e626f2db6eadc86993b5b8`.

The native patch checks the actual standard-input descriptor before each outer command read and before the interactive global-command read in `main_loop.c`. It uses the existing `code-file-policy.h` reader policy, SHA256 `64e344ca44ea9859708b0f84fe3c8a41c6a56942eafc3e05a75a1f00434fbea2`: confined regular command input requires a read-only executable mount; nonregular terminal/pipe input remains allowed. The diagnostic is `ConfOS: Permission denied for saved code input`. No command-text filtering or executable wrapper is introduced. Document reads, append text, and output writes remain in their original data-reading paths. Command continuations use the same already checked standard-input descriptor; inspection found no standard-input replacement path.

The Debian `red` is an 89-byte regular shell launcher, not a symlink. Its original SHA256 `417f37ffe30a83d9b2a7e0340e57e46018f6ee6919ee1b6f63b791d716c3f65a` is preserved. It invokes the adjacent ed with `--restricted`; its shell restrictions must remain distinguishable from the new descriptor refusal.

The recipe retains Debian hardening options and uses one compiler job. Worker tools are GCC `14.2.0-19`, binutils `2.44-3`, dpkg-dev `1.22.22`, make `4.4.1-2`, and libc development/runtime `2.41-12+deb13u4`. This is an explicitly recorded rebuild environment, not a claim of Debian bit-for-bit reproduction. The private guest selects libc `2.41-12+deb13u5`; no replacement library is shipped. Candidate and original require only `libc.so.6`, have equal symbol-version requirement sets (highest GLIBC_2.34), equal version output, and equal exported dynamic symbol names (`stdin`, `stdout`, `stderr`). The full upstream `make check` suite passes.

Two failed native observations are retained. Direct helper inclusion initially failed because `ST_NOEXEC` was unavailable without GNU feature declarations. Enabling `_GNU_SOURCE` in the existing command translation unit compiled and passed tests but added `__isoc23_strtol@GLIBC_2.38`; the ABI assertion rejected that candidate. The final design compiles the unchanged policy helper in a separate GNU-feature translation unit and leaves the original command parser feature environment intact. A subsequent evidence-only check corrected the symbol-name parser to compare actual names rather than trailing readelf version indices; candidate bytes were not changed.

The private guest derives only from sealed41 source SHA256 `2c73f6a664a2754cc78a7244d31bb77c7ac3d5253f45653a3c12cdfb418e4ca9`. Its private optional-reader manifest adds only `/usr/bin/ed`, with exact original hash and candidate hash; inherited payload bytes remain unchanged. All 22 actual guest controls passed. Original saved regular input executed the marker. Candidate regular input, tmp/shm files, symlink/hardlink, proc/dev-fd aliases and red regular input were denied with the exact helper diagnostic and absent marker. Recorded input, recorded descriptor alias, typed pipe, actual terminal input, and explicit data producer pipe under REVIEW R4 succeeded. Original and candidate document read/edit/write preserved shell-looking text as data. Red retained its separate restricted-shell error and allowed relative document edits. A separate syntax-error control reported `Unknown command`, without a policy diagnostic. Installed executable/red hashes and original/candidate version output matched expectations. The guest was stopped and disposable image/build trees removed; retained worker inputs/evidence occupy 4.6 MiB. This is a bounded observed result (`1`) for this matrix; independent review remains pending.

The installed image's libc and dynamic loader were separately hash-compared against the exact selected `libc6_2.41-12+deb13u5_amd64.deb`, SHA256 `b59b0625cd1a791375d40dab23a4d5d3d0641e3d0a773501becdc3725b7f99cf`. They were unchanged. This image inspection is distinguished from the original/candidate version and behavior checks performed inside the guest. Native-build libc u4 and guest libc u5 are explicitly different security versions.

Reproduction uses `prepare-ed-reader-draft.py`, `build-ed-reader-draft.py`, `verify-ed-reader-abi-draft.py`, `build-ed-reader-guest-draft.py`, `run-ed-reader-guest-draft.sh`, and `probe-ed-reader-guest-draft.py`. Heavy execution requires the existing worker, persistent limited user unit, and shared guest slot. `collect-ed-reader-draft.py` preserves input, source, patched-source, candidate, fixture, and failure evidence before removing disposable build and guest trees. Paths in published logs are normalized to `<build>`; upstream source and binary debug information are not rewritten.
