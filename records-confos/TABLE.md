# Version 5 statements and the checks on ConfOS 0.55

The statements follow Section 5 of the [sixth paper](../sixth-paper/paper6-en.md) in order. They are short English renderings for this mapping, not a replacement definition. Sentence IDs refer to [SENTENCES.md](../records-v4/SENTENCES.md); §8.4 and §8.5 refer to [paper 4](../fourth-paper/paper4-en.md).

Evidence keys: **C** = [confos-check/CASES.md](../confos-check/CASES.md), the case definitions; **R** = [RUN-3.md](RUN-3.md), raw outcomes; **J** = [REVIEW.md](REVIEW.md), review decisions; **F** = [RUNS.md](RUNS.md), run 3 after review; **X** = [RUN-3-EXTRA.md](RUN-3-EXTRA.md). Counts of subsets are counts of the named rows in C and R; aggregate counts are R's “Rows by part and outcome” and F's run-3 entry. Subsets overlap and must not be added across statements.

The text's result and the plan's verdict are not interchangeable. `unclear` marks a question the cited records do not decide; the reason is stated in the cell. **A. Complete-run-3 verdicts that would differ under version 5:** none.

The comparison uses version 4's reviewed verdicts in F, with the raw outcomes in R, against every changed statement of version 5: K1/W5a concern the system's refusal and installation/configuration; W1e uses the declaration in force (C, common decisions; J R8); Q2 includes the recorded update of OW-8 (J R2/R3/R8); Q3/Q4 keep direct-file refusal distinct from typed input (J R1/R4/R5), and no run-3 case performs R10; Q7 retains the classification of C's alias, hook, autostart and SSH cases.
W3e keeps dependencies and built objects under their source lines (C, REM-4; J, Not decided by the review); W4a/Q3 encounter no opening line in 0.55, and W3d's omitted-identifier case remains unobserved (R, REPRO-2b). The FAQ introduction changes no requirement; the plan's real-hardware, recording-tool and derivation conditions remain unchanged, and E1–E3 remain outside the comparison.

**B. Tested version-4 formulations with no explicit counterpart in version 5:**

- S8.3-7's affirmative duty to add the request to the declaration, rather than refuse: REC's 10 requests were recorded; the positive application/removal checks are E1, beyond the plan. K1/Q2 retain the system's default prohibition on changes past the declaration, including through a program's additions and updates, but not that affirmative duty (J R3/R8).
- S8.2-6's ordered four-question decision procedure: C applies it in the 152 P1 rows. Version 5 states the categories and their consequences without that ordered procedure; the resulting object verdicts are retained.
- S8.1-4 and S8.1-7's documentation-based classification, and S8.1-6's definition of a package as the installation/removal unit (including an image): C uses these classifications for P1/P4, but records no separate verdict on each definition. W2a/W3b/Q2 preserve the relevant behavior; these separate definitions are absent.
- S8.2-19's express permission to record things that need not be recorded: `D-test.spec` records the harmless Git alias `st=status`; `adapter.py` renders it as a file line. P2-all checks declared file contents (43 pass). Version 5 does not repeat that blanket permission; its unspecified choice of line kinds does not prohibit it.

These omissions of explicit machinery and vocabulary are distinct from changes to system requirements. The content changes of version 5 are the recording duty, the treatment of personal code files, and the replacement of “all recorded/visible” by “silent means absent”; none is stricter.

**C. Statements not tested on the stand (eight; `unclear` where an observation is missing):**

- N: the definition's binary classification is not an empirical case.
- W1d: unclear — no case varies the number of files forming the declaration.
- W3d: unclear — omitted identifiers are not expressible; no “newest version” case exists.
- W4a: unclear — no line that opens this is present in 0.55; the current wording does not require that the person wrote it.
- W4c: no case compares an initially open path with an added prohibition.
- W5b: non-refutation by breaking is a judgment rule, not a tested effect.
- Q1: unclear on the stand — no opening-line case; the answer is reasoning from the core.
- Q9: unclear — no case supplies accounts from a named external server.

W1e and W3e state how words are used and are exercised by existing comparisons; they are not two additional untested statements. W3e's values left open remain unclear for W3d's reason. Partially tested statements retain their specific omissions: successful breaking in W5a, untried updaters in Q2, Q4's recorded file-reader on 0.55, Q6's guest system, Q7's theme/home page and Q8's listening-port attribution are unclear where no case decides them; R10's probe is outside run 3.

**Statements without a row.** The section “What the definition does not decide” (seven items left to the design of a system: no case applies) and the first lines of “Frequently asked questions” (a note on where the section stands) have no row. The clause added to the sentence about silence (“nothing is written” and “says not a word” mean the same) says how words are used and has no row either.
