[STAND.md](STAND.md) maps each of the 45 individual rows to these tests. The mechanism uses existing AppArmor, Landlock, seccomp, ownership/modes, chroot and systemd before the small static input/launch adapter. It is not a command-name patch: every future admitted program defaults to the sealed input domain, and execute/map rights are generated from current declaration membership.

The ordinary user can type only a tab-separated selection: `run<TAB>declared-entry`, documented value arguments for a fixed data tool, or `broker<TAB>named-frontend<TAB>values`. A document-writing request accepts subsequent stdin bytes verbatim. No shell parsing, expansion, pipeline, function definition or free command evaluation occurs. [HOWTO.md](HOWTO.md) gives the exact protocol and a complete checksum-bearing recorded-script example.

The cost is deliberate and substantial: no general REPL, arbitrary host build commands, free script arguments, writable imports, executable project/editor configuration, native JIT or extension-capable ordinary browser. A recorded script cannot read arbitrary user documents or receive network/IPC instructions. Document editing is whole-document replacement with fixed `dd`, followed by `cat`; browsing is passive `w3m` output. Declared installation/update, recorded code, document editing and browsing remain exercised through the boundary. Existing saved-network/prepared-Bluetooth workflows are rerun; their hardware limits are unchanged.

For TEXT-OPEN C7.18 and C7.21, the implementation follows the stricter reading: executable cache/module inputs need recorded membership; no cache or partial-runtime-rights exemption is assumed. Unrecorded bytecode and executable JIT memory refuse, and the explicit WASI preopen/runtime request refuses because that ordinary interface is removed. This does not decide the textual ambiguity.

Managed service setup is explicitly recorded: systemd starts the fixed static launcher as root in its protected cgroup and generated profile; it enters the immutable root, permanently drops supplementary groups and UID/GID, clears inheritable/permitted/effective/ambient capabilities, then locks no_new_privs before workload execution. The output relay also drops identity/capabilities and locks no_new_privs. Verification reads the relay's stable runtime identity, capability sets, no_new_privs and profile; descendant confinement additionally depends on the common launcher and the actual lifecycle probes. The service manager's early no_new_privs setting was deferred after diagnostics showed setup lacked CAP_SETUID and could not drop UID when it was enabled; failed runs and the capability diagnostic are retained in (not published: record outside selected evidence).
