# Observation collector preparation check

Recorded 2026-11-23 UTC. This is one collector integration check on a disposable copy, with no update, development, game or network-interruption history executed. The expectation was saved before the command in `observer-smoke/expected.json`; exact executed source is `observer-smoke/observer-source.py` and its hash is `observer-smoke/source.json`.

The check returned one parseable complete JSON (exit 0), independently enumerated 72,972 filesystem entries, emitted all 559 initial machine rows and all five filesystem descriptions. It retained explicit native errors/limits. **The declaration and success reports changed during collection.** This is not a passing stable observation, and is not a history or hypothesis outcome. `observer-smoke/summary.json` and losslessly compressed `collector.stdout.gz` retain it; `compression.json` supplies the exact uncompressed size/hash. The uncompressed output remains on the host, and can be reconstructed byte-for-byte with `gzip -dc collector.stdout.gz`.

Saved before/after comparison (`observer-smoke/stability-differences.json`) locates the changes at the private temporary directories of `systemd-localed.service` and `systemd-timedated.service`, in both mediated temporary filesystems. The first query draft used `localectl status` and `timedatectl show`, which can activate their D-Bus services. It therefore perturbed the declaration it was observing. This limitation was detected, retained, and corrected in the observation inputs before commitment; the image was not changed.

The final collector uses `busctl --system --auto-start=no --allow-interactive-authorization=no call ... org.freedesktop.DBus.Properties GetAll s INTERFACE` for those two services, and directly retains their saved configuration files. The primary [busctl manual](https://www.freedesktop.org/software/systemd/man/latest/busctl.html) documents `--auto-start=` for `call`: “specifies whether the method call should implicitly activate the called service”. It was added in version 218, before the image's recorded systemd 257. An inactive service returns unavailable properties; the collector does not launch it, replace that error with defaults, or discard a changed generation. The documentation answers this correction's behavior; there was no repeated VM probe of the same shape.

The corrected final source receives syntax/static validation and is separately bound by the final input seal. The earlier executed-source checksum must not be presented as the checksum of the corrected collector. The disposable observation guest was stopped and its overlay deleted (`observer-smoke/cleanup.json`). This integration check is a fifth preparation copy over time, not a fifth history or an additional hypothesis test; all machines used only the existing final image.
