## Why case 2b is not expressible

`stand.py:load` requires `r['uid']` for every managed account and requires 1100–60000. `expected_account` requires the keys `name`, `uid`, `gid`, `groups`, `shell`, `home`, `gecos`. The account activation path uses those numeric values; it does not provide a missing-UID alternative. `bc3_account_rows.account_rows` independently emits explicit numeric UID/GID and numeric group memberships from the prospective passwd/group bytes. Its own account-database rows also fix the complete database bytes and hashes. Thus deleting the numeric field from one machine row neither validates nor removes the identifier from the complete declaration. Native automatic allocation would subsequently record its numeric result in those filesystem account rows. No unspecified-ID line, default UID or altered account format is introduced. See [fixture source analysis](raw/round-4-prep/fixtures-12.md).

## Known limits

1. The testbed remains partial. No other STAND variant is reassessed, and this preparation assigns no hypothesis outcome. The original step-5 limitations remain, including unsupported special nodes/shared writable mappings, retained backing versions and incomplete global execution coverage.
2. Complete replay is sequential across machine state and five filesystem services; it is not an atomic whole-system transaction. A refusal or crash may leave a partially applied description, without a new complete-success report. It does not establish properties at every intermediate instant, concurrent writer safety, recovery closure or rollback. Exact-generation replay can lower a generation number, so inherited restart discovery of the preceding generation is a known retention limitation; these cases contain no reboot.
3. Replaying an input with unreachable retained inodes or an open handle lacking a unique surviving path is refused. This is a finite implementation limit, not an added hypothesis rule. Root direct editing remains possible.
4. Every stated filesystem value, including timestamps, remains in comparison. Unavailable native queries, changing declarations during observation, unsupported field interpretation, or coincident equal errors cannot be called passes. The inherited broad policy claim and external boot controls require the explicit evidence qualifications in COMPARE-6.
5. The shared package is deliberately dependency-only. Its actual installer registration is its installed object; it has no executable or file payload. Queries read that registration and origins, rather than inventing payload checks or using the requested declaration as actual state.
6. Public commitment is pending: local repository metadata is empty/read-only and no public destination is supplied. The exact files are locally sealed, but that is not a public commit. The records operator must publish the unchanged sealed inputs and record the commit and public URL before any second-party attempt. The runner enforces a matching seal and exclusive case-output directory. Inputs must not change after publication. The builder has not invoked the runner.
