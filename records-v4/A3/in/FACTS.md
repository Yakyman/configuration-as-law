# Recorded facts and their limits

This is an inventory beyond the four-check plan (PROTOCOL.md Section 5), not a classification or hypothesis outcome. All paths below are relative to A3/in. For each completed MACHINE (`developer`, `gaming`, `server`), the whole post-restart collector output is in `raw/MACHINE/`; its untouched-base counterpart is in `raw/MACHINE-base/`. The exact collector contract is check-inputs-v4/COLLECT.md and the manager-specific contract is C1/collector/PACKAGES.md.

- Explicit installation versus dependency: the JSON `members` field of package rows in `objects.tsv` records `reason`, manager identity, and adapter-specific reason source/rule. Raw queries and their statuses are in `coverage.tsv` and `raw/`. `unknown` stays unknown; native ownership of language metadata does not transfer a native package's installation reason.
- Change since installation: `package-files.tsv` joins its `package` column to the original collector object ID and records path, integrity, evidence and rule. The collector compares supported installation digests with bounded full-file hashes, or supported link targets/size evidence. Unsupported records, oversized files and failed reads remain unknown. Stored-member signatures cover at most the first 4096 bytes and do not prove whole-file integrity.
- Complete members: stored-group `members` points to `members/ID.tsv`, with count and traversal-completeness flag. Those tables retain every observed immediate child and path, type, mode, owner, size, mtime, executable flag, signature and persistence. An incomplete traversal remains explicitly incomplete; no sample is represented as a complete group. Native package paths/integrity are in `package-files.tsv`; unsupported package-manager manifests remain a coverage limitation.
- Persistence: member-table `persistence` and individual object metadata come from the collector's filesystem-type detection. tmpfs/ramfs are runtime, normal stored filesystems persistent, and overlays or failed detection unknown. This does not promise that a disposable disk or container will be retained. Action logs and before/after boot IDs document the required single restart; system/user units, timers, autostart state and runtime objects are only what the post-restart collector observed.
- Configuration provenance: `configuration-origin.tsv` records candidates, timestamps, maintainer-script mentions and installation-log references. mtime and ctime do not establish creation time or causation; `created=unknown` is not replaced with a guess.

`metadata.json` records filesystem/ownership completeness and gaps. `coverage.tsv` records every query's exit status and output references. Collector exit status is separately retained in `operator/MACHINE/`; a zero controller exit does not erase query failures. Missing commands, unavailable managers, unsupported Homebrew/Ruby or other adapters, incomplete traversals, timeouts and output caps are not interpreted as object absence.

The reduced tables preserve original `members` bytes. Resolve their relative file paths under the `inventory_root` named in the evidence cell. The added source-row reference retains the original collector ID, which is also the join key for `package-files.tsv`. Both inventories and all query/member evidence remain available after base-equal rows are dropped from the derived table. REDUCTION.md specifies the exact equality comparison; READY.md reports observed completion, action failures and deviations.
