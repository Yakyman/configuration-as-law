# Questions noted by c2 (part developer); not decided here

- Readings for the author: does "what an installer installs and removes as a whole" (S8.1-6) require one installer to do both? (juliaup: installed by its init program, removed by `juliaup self uninstall`.)
- Readings for the author: a setting value written by a program at its first run, chosen by no person and not created during package installation (dockerd's firewalld zone): setting covered by S8.2-17, or program record by Q3/Q4?
- The text does not mention directories or symbolic links; c2 decided them by Q1–Q4 (directory written by a program → record; link read as a value → not code). An author reading may differ.
- Q2 makes code in caches (bun package cache, Go module cache) and in cloned projects programs that must be recorded, before Q4 "cache"/"projects" is reached; c2 applied the order as written.
- (part gaming) Readings for the author: is a client that an installer installs for itself and removes whole (Steam client via its updater and `steam.sh --reset`) a "package" of that installer (S8.1-6), or is an installer's self-installation outside S8.1-4/S8.1-5? c2 recorded GAP-TWO for the whole Steam client tree.
- (part gaming) Readings for the author: web-page code shipped with a program (SteamCMD web UI JavaScript) is a program by S8.2-9, yet S8.2-21 says such code need not be recorded; no decision word covers "a program that need not be recorded".
- (part server) Readings for the author: is Docker (or containerd in k3s) an installer under S8.1-4? Its documentation calls an image "a standardized package" of binaries and pulls/removes it whole, but never says it installs programs; the answer decides whether a container image is an installed object (Q1) or a program (Q2). c2 recorded GAP-TWO.
- (part server) Readings for the author: a crontab line is read by cron as schedule values while its command field is executed by /bin/sh; S8.2-23 does not say how to decide a file that is partly executed. c2 recorded GAP-TWO (PROGRAM-OWN or SETTING-OWN).
- (part server) Readings for the author: one store holding both a person's settings and a program's working state (k3s state.db with the applied workload): setting by "whatever file stores it" (S8.2-12) or program record (S8.2-15)? c2 recorded GAP-TWO at member level.
- (part server) The inventory does not collect the contents of person-written configuration files (compose.yaml, unit files, nft ruleset, cron and logrotate files) nor dpkg control-area integrity or update-alternatives modes; several c2 decisions are UNKNOWN only for that reason.
