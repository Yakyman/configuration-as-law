1. **Strongest objection: the line must already state its requirement.** S8.1-12 can be read as requiring each admitted line to have enough meaning to determine its required state; S8.3-5 delegates to that meaning. A primitive taking an external list can have a documented snapshot, current-list or offline policy without spelling the entire policy out each time. Under this reading, the example has not supplied a complete admitted line. The counter-reading is that S8.2-18 expressly permits the named source to count as recorded, but supplies no time rule, so the source-only line is admitted with the temporal question unanswered. S8.1-12 does not itself choose a time. These are competing readings of two identified sentences, not a choice of caching policy made here. The registered author-reading rule therefore applies: **?**.

2. **Unknown implementation semantics would be missing facts.** If L belongs to a real language whose documented semantics select a list, those semantics determine its requirements through S8.1-12. Failure to collect them is **FACT_UNKNOWN**, with the missing fact being the defined meaning of L; it is not a textual gap. No real-language fixture is asserted here. Likewise, failure to collect the remote list in a real observation would be FACT_UNKNOWN. Both remote values in B2 are stipulated, so that distinct issue does not explain the candidate temporal ambiguity. Different systems choosing different defined policies is not a gap.

3. **Several permitted outputs need not mean an undetermined requirement.** A line may permit more than one state. A specified rule allowing both retained and current lists would decide that the B2 retained list is acceptable. The disputed question is whether it is acceptable under the source-only line at all: the snapshot reading accepts it and the current-source reading rejects it. No uniqueness requirement is being added. If the source-only line itself means provenance without freshness, that is the third table reading: retained {account-A} is permitted, while another list qualifies only if obtained from R. This too requires author resolution; no policy is silently adopted here.

4. **The external-source exceptions do not settle the offline requirement.** Section 8.4, quote: “For a line that takes a list from outside the declaration, the declaration shows which source determines the list.” Also, quote: “For a line that takes a list from outside the declaration, reproducibility is not claimed.” These defeat a demand to reconstruct the list from the declaration alone or reproduce one fixed list across machines. Neither states an offline waiver of S8.3-1/P2 or selects a time. Section 8.5 permits algorithmic declarations and excludes design mechanisms; it prevents treating the lack of one universal caching mechanism as a gap. It does not expressly answer whether an admitted source-only line may lack any temporal meaning.

5. **A cache label and P4 do not supply the missing meaning.** Accounts are settings under S8.2-13, regardless of storage. S8.2-6: “What an object is is determined by four questions asked in order; the first affirmative answer decides, and the clarifications do not change this order.” A program-record classification cannot bypass earlier questions merely because a file is called a cache. Conversely no cache behavior is assumed here. P4 (S8.3-6–8) forbids an ordinary bypass; it does not make every change obtained from a named source a bypass, since S8.2-18 expressly allows that source. Neither rule chooses between the candidate lists.

The tempting universal-impossibility chain would be: S8.2-18 names R; therefore its **current** contents must hold; S8.3-1 applies offline; P2 (S8.3-5) then requires unknown remote changes immediately.
