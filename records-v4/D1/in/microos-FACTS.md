### microos

All collector output is under `D1/in/raw/microos/`. Strip `microos-` from a part-table `id` to recover the original `objects.tsv` `id`. The source columns are `id`, `machine`, `level`, `kind`, `name`, `members`, `evidence`. All source rows and their original machine/name/member/evidence fields are retained in collector order; only the part, id prefix and level-prefixed kind are added. Evidence paths below are relative to that machine's raw directory.

- Package reasons: `D1/in/raw/microos/objects.tsv`, `kind=package`, JSON field `members.reason` gives `explicit`, `dependency` or `unknown`. Other JSON fields include `manager`, `native_reason`, `reason_rule`, `selected_group_records`, `version`. The row's `evidence` cites the exact native queries; for RPM these include `D1/in/raw/microos/raw/0007-packages-rpm.out`, `D1/in/raw/microos/raw/0008-package-reasons-dnf.out` and `D1/in/raw/microos/raw/0009-metadata-read-0.out`. On this machine DNF is unavailable; the latter metadata query retains the native zypp AutoInstalled record. Do not replace the collector's reason by a guess from `native_reason` or a package name.
- Packaged-file integrity: `D1/in/raw/microos/package-files.tsv` columns `package`, `path`, `integrity`, `evidence`, `rule`. Join `package` to the original object id. `unchanged`, `changed`, `missing` are known; `unknown` remains unknown. The table preserves every collector package/file record, including multiple ownership when present. Directory ownership is outside this table's denominator, as implemented by the committed collector.
- Complete group member lists: each stored group's JSON `members.file` points to its exact (not published: record outside selected evidence); `members.count` gives the row count, and `members.complete` records traversal completeness. Columns are `path`, `type`, `mode`, `owner`, `size`, `mtime`, `executable`, `signature`, `persistence`. These are the complete lists emitted by the collector, without sampling or further merging. No membership file is invented for objects whose collector representation is opaque.
- Stored-object persistence: group member tables above have the `persistence` column for each `path`. For an executable-code row, `objects.tsv` JSON `members.persistence` is the directly captured fact; opaque image/snapshot rows use `members.metadata.persistence`. For a directory group itself, match its `name` to `path` in `D1/in/raw/microos/raw/0004-filesystem.out` (newline-delimited JSON), whose fields include `persistence`, `filesystem`, `readonly`, `type`. The same file is the raw per-path source for member metadata. A missing record or `unknown` is not resolved from a parent path. `persistent` and `runtime` refer to the mounted filesystem, not to whether the disposable VM will be kept.
- Limitations and exact query failures: `D1/in/raw/microos/coverage.tsv` columns `query`, `exit_status`, `duration`, `rows`, `bytes`, `stdout`, `stderr`, `status`, `object_rows`; each `stdout`/`stderr` links to the unchanged query result. `metadata.json` records `filesystem_complete`, `package_ownership_complete`, `gaps`, UTC time and duration. There are 17 nonzero query statuses, including unavailable interfaces; no query was repaired or repeated. The committed collector records complete traversal and ownership coverage for its implemented scope, without asserting universal manager coverage.

For `L1:group` rows, `D1/in/raw/microos/objects.tsv` JSON `members.record` retains the entire captured `/etc/group` record (name, password placeholder, numeric group id, comma-separated named members); `evidence` points to `D1/in/raw/microos/raw/0003-metadata-read-0.out`. This is the source group record, not a synthesized list of all effective account memberships. The captured `L1:account` records preserve primary numeric group ids separately.
