## Flatpak and its containing share group

`raw/0030-packages-flatpak-user-1000-app.out` establishes the Calculator deployment; `raw/0031-packages-flatpak-user-1000-runtime.out` lists four runtimes. The package objects in `objects.tsv` mark the application explicit and the runtimes dependency, but explicitly qualify the inference as application/runtime distinction rather than historical user intent. The physical member table contains additional Locale deployments, repository objects, repository configuration, trust keys, generated deployment metadata, exported entries, `.changed`, and `repo/.lock`. The containing share group's only immediate member is the same Flatpak store, and its expansion is followed rather than ignored.

The official [Flatpak internals documentation](https://docs.flatpak.org/en/latest/under-the-hood.html) says: “each application, runtime and extension is a branch in a repository.” It explains that installation pulls branches and generates filesystem hard links. This establishes the role of these paths, not that every present member remains as received. S8.2-7 asks whether a package member remains as received before S8.2-9 asks whether it is code. No original-reference comparison for these store members is delivered. The inventory cannot establish a full member partition into INSTALLED-PACKAGE, PROGRAM-OWN/DERIVED, and records. The aggregate result is UNKNOWN, not an assertion that the store is homogeneous, and not a claim that no installed application is known to exist.
