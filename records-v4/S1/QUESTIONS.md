# Author questions from step 1

Recorded 2026-11-23 UTC. These questions identify readings of the fixed text; they are not proposals to change it or requests for a new experiment. The sentence quotations are collected in `S1/ARGUMENT.md`.

1. **What does “unambiguous” require?** In Section 8.4, does it mean that a requirement has one clear meaning, or that it allows only one relevant result? For example, “create this account using the first free identifier” is a clear rule, but different allowed installation orders can give the account different identifiers. Under the first reading that declaration may qualify; under the second it does not. This choice affects the Reproducibility outcome.

2. **Which result must be reproduced?** Does “exactly the result described in it” in Section 8.4 mean that the stated requirements hold again, or that all covered configuration values are identical, including values the lines leave to installation? Appendix A.4.4 compares numeric account identifiers and file checksums in addition to stated values. Are those additional fields necessarily determined by every qualifying description, or can a description clearly permit more than one value? This choice also affects Reproducibility; the argument does not change the published comparison procedure.

3. **What happens to unchanged non-code package contents when the package is gone?** In S8.2-7, does “such a package” require the package to be installed now, or does historical receipt from that package suffice? The first reading sends a surviving file through the later questions; the second can keep it installed. This affects classification of a remnant, not the proof that a currently installed object or setting cannot remain in force without coverage. No actual remnant's missing provenance is supplied by either reading.

4. **Does voluntary recording change the removal scope for material and program records?** S8.2-19 permits recording them and P2 speaks of everything recorded. Section 8.5 leaves their storage, transfer and removal outside the definition. Does that boundary continue to apply when such an object has been voluntarily recorded, or is “nothing the line contributed” in Section 8.4 intended to extend to it? The argument retains the explicit boundary and uses no retained document as a counterexample. Section 8.5 itself is not a gap. Question 5 separately concerns an account that is in force by type even if its classification is a record; it cannot be dismissed by claiming that all records lack a force criterion.

5. **Who must choose an installation-created account for Q3 to apply?** S8.2-11 says “a value chosen by a person”; S8.2-13 lists accounts among settings, and S8.2-6 preserves the ordered questions. If a package creates an account that the person never explicitly requested, does choosing the package (or its author's choice) count as choosing that account, or must that account itself have been chosen? On the former reading it is a setting and P1 forbids its uncovered survival. On the latter, if Q1 and Q2 fail, it can reach S8.2-15 as a program record. Yet S8.1-11 makes an existing account in force. Does Section 8.5's explicit exclusion for records place that account outside Removal, or does Section 8.4's “nothing the line contributed is in force” still include it? The text does not expressly say “the person of this computer”; that restriction is a candidate reading, not a rule supplied here. The conditional pair and the objections to it are in `S1/ARGUMENT.md` §5. Unlike question 4, this account was not voluntarily recorded.

The first two questions prevent a definite Reproducibility result under `SUP1/step-1.md`. Question 3 does not defeat the restricted P1 implication for installed objects and settings. Question 5, including its relation to the exclusion discussed in question 4, prevents extending that implication to full Removal: its outcome is ?. Understanding's pair directly records expressly requested accounts; it does not depend on resolving the unrequested-default question or on default coverage.
