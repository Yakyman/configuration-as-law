Exact Compose, workload, proxy, service, timer, cron, firewall, administrator, sysctl, swap and log-rotation inputs are embedded in `lived-server.sh`. Containers and the K3s workload remain running. Database rows and passwords are synthetic guest-only fixtures. Exporter traffic and the Compose frontend are published only on guest loopback. No domain, external service account, payment or real SSH key is used. Do not publish the newly generated private key.

Docker/Compose, Caddy, PostgreSQL, K3s and Node Exporter differ from the preceding build's Podman, nginx/Redis and Netdata where a choice exists. Cron, systemd, nftables, sudo, OpenSSH and Linux administration interfaces remain the native implementations of explicitly required channels. The compose file is written locally rather than copied from the earlier public example project.

The cloud filesystem must permit an ordinary non-sparse swap file (such as ext4). The file is added to fstab only after successful activation. K3s is configured with `fail-swap-on=false` before swap is added. Its default pod subnet is explicitly allowed through the server input firewall; this ruleset intentionally does not replace container forwarding/NAT policy. The firewall is loaded through its own boot unit without `flush ruleset`, so it does not erase rules installed by the engines. The new administrator rule is narrow and remains an actual sudo rule.

Release selectors are part of the fixed commands: Docker's stable repository, K3s's default stable installer channel, the stated container tags and the explicit Node Exporter release. Their resolved versions are runtime evidence for C1-REH. The Debian codename is read only to construct the repository appropriate to the selected base. No rehearsal or acceptance is claimed by this documentation-only preparation.
