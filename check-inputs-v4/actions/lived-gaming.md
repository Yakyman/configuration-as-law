# Lived-in gaming machine: fixed actions

This is the fixed action recipe and its preparation history. Completed rehearsal results are recorded separately in `READY.md` and `rehearsal/mint/`; planning statements below do not supersede those records.

Base: a disposable copy of the previous night's clean Linux Mint 22.3 Cinnamon installation. Run `bash lived-gaming.sh` as ordinary account `user` in its existing Cinnamon X11 session, with `DISPLAY`, its authorization and its session bus available. The Steam and Lutris GUI drivers each use `xvfb-run -a dbus-run-session -- python3` with a private virtual display and session bus. Prerequisites include `xvfb`, `xauth` and `dbus-daemon`; these instrument prerequisites provide GUI access over SSH. The existing per-action limits still bound the wrappers and clients. The machine needs a virtual audio output; no physical graphics accelerator, game account, purchase or personal data is required. Use default XDG directories, as on the clean installation. Administrator commands use the shared `root` helper, through sudo. Mint's normal Ubuntu `universe`/`multiverse` repository components must be enabled, as in the clean installation. A missing repository or session capability is an action failure, not permission to substitute another action silently.

The script has **9 actions**, including explicit prerequisites. `lib.sh` bounds every action and writes one name/status/duration line to `~/actions-status.tsv`. Limits below are seconds. These are documentation-derived inputs, not observations: machine execution and its failures are recorded under `rehearsal/mint/`. The action list is final; any rehearsal replacement must give its reason.

## Unattended Steam bootstrap

The exact [Ubuntu noble packaging source archive](https://archive.ubuntu.com/ubuntu/pool/universe/s/steam-installer/steam-installer_1.0.0.79~ds-2.debian.tar.xz) was read without running its code. `debian/steam-installer.templates` contains only `steam/need-nvidia-i386` and `steam/purge` notes, so no invented `steam/license` or `steam/question` preseed is used. `debian/scripts/steam.in` instead opens a first-run Zenity question titled **Steam installer**, with `--ok-label="Install"` and `--default-cancel`. The script enables toolkit accessibility and invokes that exact dialog's **Install** button through AT-SPI, scoped to the Steam process group. It does not accept unrelated dialogs. The package wrapper downloads, checks its own SHA256, unpacks the bootstrap and writes `deb-installer/version` itself. Completion requires this marker, the runtime and client files, and a live `ubuntu12_32/steam` executable; merely creating the initial directory cannot count as success.

The [AT-SPI `get_action_iface` API](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_action_iface.html) explicitly “Gets the `AtspiAction` interface for an `AtspiAccessible`.” This is the interface used by both GUI drivers. The [`/proc/pid/exe` manual](https://manpages.debian.org/bookworm/manpages/proc_pid_exe.5.en.html) documents executable identity; the [Python OS API](https://docs.python.org/3/library/os.html#os.getpgid) documents process-group checks.

The [Unturned publisher's SteamCMD instructions](https://docs.smartlydressedgames.com/en/stable/servers/steamcmd.html) specify the default directory as `.../steamapps/common/U3DS/` and its Linux launch helper as `./ServerHelper.sh`. The script now supplies an explicit `+force_install_dir` before login and checks `~/Games/U3DS/ServerHelper.sh`. The [client maintainer's instruction](https://github.com/ValveSoftware/steam-for-linux/issues/8298) specifies that destination selection precedes login. This repairs destination ambiguity while preserving the same anonymous application download.

## Unattended launcher installation

The [Lutris 0.5.17 CLI source](https://github.com/lutris/lutris/blob/v0.5.17/lutris/gui/application.py) registers `--install`; it does not register `--unattended`. No such switch is assumed. The exact 7-Zip installer YAML is embedded in the shell function and is interpreted by Lutris. The helper only invokes visible, sensitive **Install** or **Continue** buttons; their definitions and page transitions are in the [installer-window source](https://github.com/lutris/lutris/blob/v0.5.17/lutris/gui/installerwindow.py). It does not copy game files into place or edit the launcher's database.

The helper is restricted to the supervised process group using [AT-SPI `get_process_id`](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_process_id.html), which “Returns the process id associated with the given accessible.” Toolkit accessibility is enabled through Cinnamon's documented `toolkit-accessibility` setting. A fresh machine must not already have Lutris running. A 600-second monotonic deadline fails if no installation completes. Completion requires both an installed record and its executable on disk. The read-only query follows the launcher's [`games` table](https://github.com/lutris/lutris/blob/v0.5.17/lutris/database/games.py), CLI `installed` filter, and [`pga.db` location](https://github.com/lutris/lutris/blob/v0.5.17/lutris/settings.py). A dialog remaining open, an elapsed wait, or a zero launch status alone never counts as installation. Errors or changed UI labels produce a failed action for C1-REH to report.

## Exact execution and retained state

All exact commands, YAML, overlay configuration and desktop entry are in `lived-gaming.sh`. The adjacent `gui_guard.py` supervises GUI process groups in the original action session. A controller pipe closes even after a hard controller termination, requesting bounded TERM/KILL cleanup; both guardian and controller certify that no live group members remain. A wrapper may hand off to a child without a premature-exit failure. This uses the Python subprocess pipe/process-group API and the documented `/proc/pid/stat` process state; zombie entries are not live clients. Basic shell file creation, directory creation, archive unpacking, file checks and removal are conventional operations. Download options are documented by [curl](https://curl.se/docs/manpage.html): `--fail`, `--location`, `--connect-timeout`, `--max-time`, and `--output`. Child-process launch, deadlines and cleanup use the [Python subprocess API](https://docs.python.org/3/library/subprocess.html); database confirmation uses [Python sqlite3](https://docs.python.org/3/library/sqlite3.html). [AT-SPI Accessible](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/class.Accessible.html) documents traversal, roles, state and action access. [Bash](https://www.gnu.org/software/bash/manual/bash.html) documents `trap` and shell error handling.

Installer caches and user application state inside the disposable machine remain for its inventory. Temporary SteamCMD bootstrap archives are removed. Initial Steam/Lutris processes and prefix-specific Wine helpers are stopped after their action. The autostart entry is retained for a later graphical login. The list changes the previous night's applications: Steam, SteamCMD, GNOME Chess, Lutris, 7-Zip, Wine and MangoHud were absent from that build; infrastructure dependencies such as Python are reused where required by the chosen tools.

The original action specification was documentation-derived. Subsequent repository, client-bootstrap, accessibility, audio and download rehearsals ran only on disposable clones; their statuses, repairs and limitations are recorded under `rehearsal/mint/` and in `READY.md`. These rehearsal results supersede the original preparation-only status.
