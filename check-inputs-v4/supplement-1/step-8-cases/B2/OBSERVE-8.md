# Step 8: fixed observation queries

Prepared 2026-11-23 UTC. These are inputs, not observations or outcomes. The executable query is [cases-8/observe.py](cases-8/observe.py), used by the once-only [controller](cases-8/run.py). It imports only the existing independent native reader `/usr/local/lib/stand/bc4-compare.py`; it does not call the system's apply operation, repair state, or use `stand-verify` as evidence of its own correctness. The image and the complete initial declaration are fixed in [CASES-8.md](CASES-8.md).

The same query is used at the end of each history, after both history-1 restarts, and in history 4 immediately after each interrupted action while disconnected and again immediately after restoration. The final observation also runs after an early action failure. A failed transport produces an unavailable observation; it never authorizes changing the image or disabling its login gate. No unexpected restart is allowed to go unobserved: retain its boot ID and run this query immediately after it, without repeating any action.

## Invocation and declaration in force

The controller sends the exact collector bytes as Python stdin through the laboratory root credential; it writes no collector or observation file inside the guest. Normal connected invocation, already performed by the controller, is:

```sh
python3 lab.py run GUEST --root < cases-8/observe.py > OBSERVATION.json 2> OBSERVATION.stderr
```

Here `GUEST` and the host output name are the concrete names fixed by `run.py`, not parameters to improvise during a history. Do not rerun the query after the controller. History 4 embeds the same frozen source in its in-memory controller and calls `collect()` with the link down; it buffers the JSON in memory, signals completion on the existing serial console, and transfers it only after the host restores the link. Exact barriers and host requests are in [cases-8/h4/README.md](cases-8/h4/README.md).

S8.1-14: “The declaration in force is the declaration of the last application that the system reported as successful [3, Section 3].” The query therefore retains, before collection, at comparison and after collection:

- All eight selected primary/reference texts, their SHA-256 values and selected generation pointers.
- `/var/lib/stand/last-success.json`, `/var/lib/stand/complete-last-success.json`, `/var/lib/stand/pending.json`, `/run/stand-ready` and each filesystem generation's `success.json`.
- The machine files from the generation named by the last **successful** machine report, even if `/var/lib/stand/current` points elsewhere. Their generation identity is independently recomputed as SHA-256 of each sorted filename, a NUL byte and its exact bytes, as specified by `build/stand.py:freeze`.
- Each filesystem's shared selected declaration/success generation, checking `status`, declaration hash and its exact bytes. A missing or mismatching report leaves its authority `FACT_UNKNOWN`; current bytes alone do not prove successful application. The complete receipt, if present, is also retained; it is not silently treated as current after newer constituent applications.

The filesystem designation and per-constituent success mechanism are inherited from [BUILD-3.md](BUILD-3.md), [BUILD-4.md](BUILD-4.md), `build/bc3_filesystem.py:commit` and `build/transactions.py`. The observer does not choose a new interpretation of a disputed aggregate application. Any conclusion requiring that choice must state both readings and remain `?` under the fixed step-8 rule.

`declaration_stable` and `success_reports_stable` compare the complete before/comparison/after identities. A change is recorded as an unstable observation, not normalized away or retried. The collector retains `boot_id`, UTC start/end and native query failures. All timestamps in filesystem requirements remain requirements.

## (a) Actual objects and settings to the declaration

`independent_census()` finishes before the collector parses declaration rows or builds a claim index. Its filesystem paths and native queries come from enumeration, not from what the declaration happens to mention. The initial identity capture is only a consistency boundary and supplies no enumeration paths. The query records:

| Actual inventory | Exact source/query; coverage |
|---|---|
| Files, directories, links and special objects | `os.walk('/', followlinks=False)` plus `/dev/shm`, excluding only recursive `/proc`, `/sys` and `/dev`. For every entry: `lstat`, full type/mode/UID/GID/size/timestamps/link count/device/inode, all xattrs, regular-file SHA-256 and first 128 bytes, or exact symlink target. File identity/size/mtime/ctime are rechecked after reading. No name, extension or execute bit is used to discard a file. |
| Installed native packages, including packages without executables | `/usr/bin/dpkg-query -W '-f=${binary:Package}\t${Version}\t${Architecture}\t${db:Status-Status}\n'`. Every installed package is compared with exact backend/name/version/architecture claims. The package table alone does not prove each member remains as received. |
| Installer receipts and non-native packages | All `/var/lib/dpkg/info/*.list`, `*.md5sums`, `*.conffiles`; full `/var/lib/stand/objects.json`. Registrations and origins are actual ledger evidence, not generated from desired dependency fields. Their current owning line and realized object still require comparison. |
| Accounts, groups and membership | `pwd.getpwall()`, `grp.getgrall()`, `os.getgrouplist()`. Enumerate names, UID/GID, all groups, shell, home, GECOS and members independently of declared names. |
| Services, timers, sockets, other units | Native `/usr/bin/systemctl list-unit-files --all`, `list-units --all`, `list-timers --all`; global-user unit-file enumeration; every enumerated enabled/linked/alias system unit's full `show` and `cat`; per-user enumeration for each existing user bus. Saved unit/autostart/cron files are included in the full filesystem walk. |
| Effective rights and login | Full mode/xattr census, `sudo -n -ll -U NAME` for every enumerated account, and `sshd -T -C user=NAME,addr=127.0.0.1,host=localhost,laddr=127.0.0.1,lport=22`; ordinary `sshd -T` too. Saved authorized keys, access files and executable configurations are filesystem candidates even if no declared line names them. |
| Network and access rules | Native `ip -j -details address show`, IPv4/IPv6 `route show table all` and `rule show`; `nft -j list ruleset` for **all** tables; native `nmcli -g all connection show` and `device show`; `ss -H -lntup`. Saved network profiles and rule sources remain in the file census. |
| Devices, filesystems, time, language | `findmnt --json -o TARGET,SOURCE,FSTYPE,OPTIONS`, `lsblk --json -O`, `bluetoothctl show`, `bluetoothctl devices`, `busctl --system --auto-start=no --allow-interactive-authorization=no call` with `org.freedesktop.DBus.Properties.GetAll` for the existing time/language services, `loginctl list-users`; `sysctl -a` lists exposed effective kernel settings. Exact time/language configuration bytes and `/etc/localtime` are also read. Inactive D-Bus services are not started to query them; their unavailable properties stay unavailable. Exact argv and every exit/stderr are retained. |
| Runtime creators and retained code | Each visible PID's executable link, argv, stat/starttime, status, mappings, mount namespace view and descriptor links; `/proc/cmdline`, root mountinfo and loaded AppArmor profile state. Deleted/open executable references and backing-generation files are included as candidates, not ignored because their paths are no longer current. |

For **each** census entry the performer records its kind, evidence path, ordered classification facts, required/not-required/`FACT_UNKNOWN` decision, exact covering line(s), relation (`own`, `package`, `derived`) and native-state comparison. `p1_file_relations` compares every independently enumerated pathname against every applicable exact own-file or filesystem-object claim; mismatches retain each field's two values. `p1_package_relations` separately compares every installed package. These are candidate relations, not a semantic P1 verdict. For enumerated accounts, services and other native settings, compare their actual entries with `p2_rows`, filesystem `account_rows` and the literal claim for that value. Retain every unmatched actual entry in the review table.

Apply the four questions **in order**, using `SENTENCES.md`; do not jump past an unknown earlier fact. S8.2-6: “What an object is is determined by four questions asked in order; the first affirmative answer decides, and the clarifications do not change this order.” Package membership alone does not establish unchanged receipt; a code signature alone does not establish executable rights; absence from one package list does not establish absence of every covering line. Link a derivation to the saved command/input/result evidence and matching output bytes. For defaults, establish actual package/default provenance. For a personal value, establish whether it launches something or grants access. When these facts are absent, name the missing fact as `FACT_UNKNOWN`, not a textual gap.

S8.2-16: “What is installed is recorded by one of three lines: a line of its own; the line of the package as part of which it was obtained; a line from which the system itself built or obtained it—a compiled copy, a generated list, a package installed as a dependency of a recorded package.” S8.2-17: “A setting is recorded by a line of its own; a default value obtained with a package or created during its installation is covered by the line of the package.” Optional recording is not a claim that every recorded document must be installed code. The complete filesystem description must be considered alongside machine lines; the old machine-only inventory is insufficient here.

What this listing cannot see or decide must remain explicit: hidden/encrypted content; arbitrary application semantics; every possible interpreter input or anonymous executable memory; all other mount/network namespaces; firmware/host state; package receipt modes absent from metadata; unobservable remote list contents; every SSH Match context or generated access command; unavailable user buses and transient processes; settings not exposed by these native interfaces. A read-only root census is not an atomic snapshot. Native commands may be absent or denied, and a failed query is not an empty inventory. Full filesystem hashes do not prove discovery of **every semantic setting**. Unresolved coverage cannot yield a P1 pass; retain insufficient data rather than claim that this finite collector is a universal classifier.

## (b) Every declaration line to required state

For every literal machine line, `p2_rows` retains the complete required object, independently queried state and `review_all_fields`. It never silently drops an unknown field. For every filesystem constituent, `p2_filesystems` retains its full JSON, every path/inode/object field, every account row, structural fields and unreachable objects. Compare all scalar/list/object values with the following interpretation of the existing format; a value without an applicable query remains an unresolved obligation.

| Requirement | Comparison |
|---|---|
| Base/program/code file or manifest | Compare each stated path/type/mode/UID/GID/hash/link target to native `lstat`/bytes/link. Check `files_manifest` content hash; decoded `content_b64` must hash to the stated checksum and equal the installed bytes by that checksum. A matching manifest text is not installed-file readback. |
| Package identity and dependency identity | Compare actual native database or installer ledger backend/name/version/architecture and registration, including dependency-only registrations and current origins. Source URLs/hashes, compiler identities and package-version metadata are provenance obligations; use the frozen inputs plus exact realized bytes, not a copied desired `source` value. |
| Account/group | Compare complete tuples and sorted numeric/named supplementary groups, including home, shell and GECOS. Missing names/GIDs or enumeration failures remain failures/unavailable values. |
| Service/timer/socket | Compare native enablement and exit; full unit text/hash; effective `cat` with drop-ins; active state if stated. A user-global unit uses its declared path and global enablement. Extra or changed security/drop-in/runtime requirements must be compared from the actual full `show`, policy and file evidence, not assumed from the unit name. |
| Privilege/login-key/password login | Compare literal file text/hash/permissions/ownership; native `sshd -T` effective password and keyboard-interactive settings. Additional per-account effective queries remain in the independent census. |
| Firewall/DAC/mount rule | Compare full nft expression/chain fields, including equivalent residual rules outside a declared table; every required DAC tuple; every required mount option against native effective options. Handle numbers are not used to suppress a stated requirement. |
| Port/native setting/profile | Compare exact protocol/address/listening boolean, native sysctl value, exact saved profile bytes and native manager values. These optional declared runtime values still require fulfillment even though runtime relationships are not separate mandatory objects under S8.2-5. |
| Boot/code-boundary prose | Compare guest cmdline and actual host VM argv/image; loaded kernel policy bytes/source hashes/launch table. Those facts do not prove universal semantic prose or host firmware control. Retain the unproved obligation. |
| Filesystem path/object | Compare **every** object field: full `st_mode`, UID/GID, size, atime/mtime/ctime, xattrs, SHA-256 or symlink target. Exact differences are emitted. Compare `(st_dev,st_ino)` classes for every pair of declared hard links. Unreachable declared objects need backing-blob/descriptor evidence; absence of a pathname does not prove absence or fulfillment. |
| Filesystem account database/semantic rows | Compare exact database content/hash and the native account/group tuples. A database-byte requirement and a semantic account requirement are both retained. |
| Format, IDs, managed flag, channel, paths→inode map, generation/next-inode and provenance fields | Preserve exact successfully selected input identity; these identify the interpreter's requirement, not a claim that Linux inode numbers equal internal keys. For any operational field (entrypoint/interpreter, application permissions, source dependency, security requirement) also identify its concrete state evidence. If this reader does not establish it, mark `FACT_UNKNOWN`; selected-text equality cannot establish its behavior. |

The native type dispatch and limitations are inherited unchanged from [COMPARE-6.md](COMPARE-6.md). Its reader is saved and hashed by the input seal. The separate finite filesystem comparison adds full current declared-field differences and the actual inode/device values required for link comparison. S8.3-5: “**P2. Guarantee.** Everything recorded in the declaration is in force on the computer as its line requires.” An unqueried field, stale success identity, mismatching value or failed reader cannot be called fulfilled. Do not erase a timestamp because it appears volatile. The reviewer must disposition every `review_all_fields` member, every structural field and every unreachable object.

## (c) Ordinary work done or not done

At each observation point, the performer freezes the cumulative action record from the host command log and available action markers. Use [cases-8/actions-plan.json](cases-8/actions-plan.json) as the required action list. Save a separate `actions-POINT.json` array; each entry has `action`, `command_record`, `started_utc`, `ended_utc`, `done` (true/false), `evidence`, and `reason` when false. A not-yet-reached action is `done:false, reason:"not yet reached"`; after a prerequisite failure use `"not reached: prerequisite failed"`. Do not omit it. This table is part of each of the three observations, including the disconnected history-4 record, whose own action stdout/stderr/exit is buffered with the state query.

`run.py` saves exact argv/stdin/SHA-256, UTC boundaries, stdout, stderr and exit for every guest session; Bash tracing includes epoch timestamps and line numbers for commands inside scripts. `ACTION_BEGIN` and `ACTION_DONE` delimit logical actions; `set -e` prevents a failed command from acquiring a later done marker. Intermediate native commands within a build/admission action remain visible in its trace. A whole-script exit 0 is not sufficient for an action whose required output check is missing.

The table can be rendered offline from the timestamped receipts for that point, including the buffered disconnected record. Do not use a later successful recovery to mark an earlier interrupted action as already done at the disconnected point. Preserve both statuses with their separate evidence times.

| Action | Required evidence to record done |
|---|---|
| Update | Installer exit 0 plus immediate native package database version/status equals the pinned newer version. Record post-restart version separately; a replayed downgrade is not concealed as persistence of the update. |
| Restart | Before/after boot IDs differ, and the new session is accessible. Keep the reboot request status even when SSH closed before acknowledgement. A VM process merely remaining alive does not prove reboot completion. |
| Fetch/edit/build/run | Exact source checksum; verified exactly one changed source line; every required source admission/compiler/result admission success; actual executable exit and exact output checksum. Six builds/runs and three edits/fetches are required for history 2. |
| Game prerequisites/install/start/self-update | Native package install/status and exact archive checksums; launcher download/install outputs; an actual game-server process and saved server output when starting; exact pinned self-updated launcher bytes. A `details` screen or wrapper exit alone does not prove the game started. The game is explicitly a dedicated server, with no local gameplay claim. |
| Disconnect/restore | Host QMP request/reply/UTC, an active matching action process at observed carrier-down, disconnected query completed with carrier still down, followed by host restore and observed carrier-up. A missed active interval is not a completed interruption and is never retried. |
| Interrupted action/recovery | Separate interrupted exit/output and, only if it failed, the single prescribed same-command retry after restoration. Do not repeat a successful action. Network-dependent inability counts against ordinary work only after restoration, as the fixed step-8 text says. |

Controller exit status is evidence of collection, not `1`, `0` or `?`. The second party assigns history outcomes under the unchanged [step-8 criteria](cases-8/criteria/step-8.md); another party reviews. Breaking is listed separately. No trial or preparation assessment is substituted for those proceedings.
